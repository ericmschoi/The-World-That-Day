## PM 미디어 결정 (2026-10-11)

- **사진과 영상은 링크로 처리하지 않는다. 결과 화면에서 바로 보이고 바로 재생된다.** 라이선스가 확인되지 않은 자료도 직접 보여 준다(PM 선택지 (c), 비상업). 원 출처가 핫링크·임베드를 기술적으로 막은 경우만 `link_only` 가 남는다.
- **촬영 시점을 모르는 미디어는 보여 주되 "촬영 시점 미상"으로 표시하고 그날 찍은 것처럼 보이게 하지 않는다. 출처가 빈 미디어는 보여 주지 않는다**(PM 결정 2026-10-11, `CLAUDE.md` 7절 1항, 제품 정의서 6.2절). 계획 반영: M3a3 "촬영 시점 미상 규칙"(날짜 범주·사건 날짜·게시일을 촬영 시점으로 옮기지 않음, `day_media` 순서), M3a4·M3a5(명시 날짜 없으면 `unknown`), M3b1·M3b1b(배지 없음 + "촬영 시점 미상"), M3b2("그날 찍힌 사진" 제목 아래에 두지 않음 — M3-P17 (a)), M3b3(영상 캡션).
- 영상: 화면에 보이면 **음소거로 자동 재생**, 누르면 소리, 벗어나면 멈춤. 움직임 줄이기·데이터 절약이면 자동 재생 안 함(M3-P8).
- **M3-P9 (b)**: 사용자가 넣은 **아무 날짜에서나** 그날 사건의 영상과 제공사 공식 임베드를 **자동으로 찾아** 보여 준다. 데모 날짜 큐레이션은 확인용 기준표로만 둔다. **영상이 없는 날짜는 사진만 나오는 것이 정상**이다(오류 아님).
- 안전장치 (PM 확인):
  1. 미디어 파일을 우리 서버·저장소에 복사·재배포하지 않는다. 원 출처 주소(핫링크)나 공식 플레이어·공식 임베드로만. (M3-P10: 자유 라이선스 자료의 Git 밖 사본 #13 (a)는 허용)
  2. 모든 미디어에 출처, 라이선스(모르면 "라이선스 확인 안 됨"), 촬영 시점·정밀도(모르면 "촬영 시점 미상"). 6.1절·6.3절 그대로.
  3. 통신사·언론사 사진은 직접 가져다 쓰기(핫링크 포함) 금지. 제공사 **공식 퍼가기(임베드)** 로는 허용.
  4. 경로 우선순위: 자유 라이선스 → 임베드 허용 공식 채널·제공사 공식 임베드 → 그 밖 직접 표시.
  5. 출처별 차단 목록(설정값)으로 권리자 요청 시 바로 내린다.
  6. 공개 배포(#5)를 정할 때 다시 본다.
- 이 결정으로 바뀐 것: #4는 "바로 재생". #18은 `display_mode` 를 표시·재생 방식(`image` / `image_embed` / `video_file` / `video_embed` / `sdk` / `link_only`)으로 개정(M3a3, 주소 형식 R9 추가). #9는 화면 표시를 막지 않는다(공개 배포 판단용).

- M3a1b와 M3a1c는 `KoWikiClient` 인터페이스로만 이어져 worktree 병렬이 가능하다(겹침: `application.yml`, `DocState`).
- M3a5와 M3a6은 서로 다른 어댑터 폴더라 M3a4 머지 뒤 worktree로 병렬 가능하다(설정 파일이 겹치면 순서대로).
- 리서치 T5가 끝나면 planner가 M3a4~M3a6·M3b3을 보정하고 PM이 쓸 출처를 승인한다.

#### 리서치 T1 결과가 바꾼 것 (2026-10-11)

- **국내(한국) 사건 날짜에는 Commons 동영상이 없었다.** 데모 날짜 3개는 모두 국내 사건이라 M3a4(Commons)만으로는 데모에 영상이 붙지 않을 가능성이 높다. 정상 동작(사진만)이다.
- 국내 사건 영상의 주 경로는 **M3a5 공식 YouTube 채널**(+ 1958~1994년 대한뉴스)이다. 그래서 **PM의 YouTube Data API 키 발급과 확인 명령(M3a5 T0)이 데모에서 영상을 보여 줄지를 좌우한다** — 리서치 머지 직후로 당기기를 권한다(아래 "PM 작업").
- M3a4의 PM 품질 확인은 세계 사건 표본(1969-07-20)과 "엉뚱한 영상이 없는지" 위주로 본다.

#### 완료 기준 요약

- **데모 3개 + 표본 5개 날짜**(1950-06-25, 1969-07-20, 1986-09-20, 2000-02-29, 2014-04-16 — 공개 역사 사건 날짜와 경계값, 실제 사람의 생년월일 아님, M3-P13 결정)에서:
  - 사건이 있으면 원문 문장·출처 링크·CC BY-SA 4.0과 함께 나오고, **같은 사건은 한 번만** 나온다(1988-09-17 개막, 2002-06-22 경기). 없으면 빈 날짜 안내.
  - 사진은 바로 보이고 날짜 관계·촬영 시점·출처·라이선스 상태가 붙는다. **촬영 시점 미상 사진은 "촬영 시점 미상"으로만 보이고 "그날 찍힌 사진" 제목 아래에 두지 않는다**(M3-P17 (a)).
  - 자동으로 찾은 영상·공식 임베드가 있으면 붙고(정확도 기준선 이상), **없으면 사진만**(오류 아님).
  - `tragic` 사건과 그날에는 영상·사진이 붙지 않는다.
- 자동 테스트는 fixture로 규칙을 확인하고, 실제 검색 품질은 PM 품질 확인(M3a4 T5, M3a5 T4, M3a6 T3)에서 기준표(`data/verification/event-media-expectations.json`)와 대조한다.
- 외부 출처 하나가 실패하거나 쿼터가 끝나도 그 부분만 빠지고 응답은 200이다. 위키백과는 날짜당 시간 상한(M3a1c)을 넘지 않는다.

## 순서를 이렇게 정한 이유

1. **M0 → M1** (완료).
2. **M3를 M1 바로 다음에** (R1 (a)): 사건 출처가 `확인됨`·키 불필요. 공용 형식·API 규약·카드를 먼저 만들어 M2·M4·M5가 재사용한다.
3. **M3 안에서**: 서버는 앞 기능의 인터페이스에 기대므로 순서대로(M3a1b·M3a1c만 병렬 가능). 웹 기초·카드와 리서치는 병렬. 영상 자동 검색은 리서치("확인됨")와 PM 키에 달려 있어 맨 뒤에 두고, 키가 필요 없는 Commons(M3a4)를 먼저 해서 검색 틀과 정확도 규칙을 일찍 검증한다. 국내 영상은 M3a5에 달려 있어 PM 키 발급을 앞당긴다.
4. **M2가 동네·도시보다 먼저**, **M4를 M5보다 먼저**, **M5a는 병렬 가능**, **M6는 마지막**.

### 순서 변경 R1 — 결정: (a) M3 먼저 (2026-10-10)

(b) M2 먼저는 PM 확인이 끝날 때까지 개발이 멈추고, (c) 동시 진행은 `server/` 충돌 관리가 필요하다.

## 가장 큰 리스크와 대응

1. **장소·지도 1순위(카카오)가 아직 `확인됨` 이 아니다** — M2·M4가 걸려 있다. 대응: PM 확인 명령을 앞쪽에, 막히면 #2 (c).
2. **동네·도시 섹션의 "그때"가 비어 있을 수 있다** — 대응: #14 (c), 정직한 안내. 2026-10-11 결정으로 서울 밖 기록 사진을 핫링크로 보여 줄 수 있어 공백이 줄어든다.
3. **사건이 비거나, 같은 사건이 여러 번 나오거나, 세계 사건이 없거나, `tone` 을 잘못 판정할 수 있다** — 대응: #21 (a), M3a1c 중복 제거(애매하면 합치지 않음), M3-P16 (b) 품질 필터, #22 (c) + 큐레이션 + 판정 불가면 `tragic`, M3a2 T5 검수, #20 후속.
4. **저작권 — PM이 위험을 알고 정함 (2026-10-11)**

   | 항목 | 내용 |
   |---|---|
   | 결정 | 라이선스가 확인되지 않은 사진·영상도 직접 보여 주고 재생한다(비상업). 아무 날짜에서나 자동으로 찾는다(M3-P9 (b)). PM은 이 선택이 저작권 침해 주장·삭제 요청의 위험을 키운다는 점을 알고 정했다 |
   | 위험 | 권리자의 삭제 요청·이의 제기, 공개 배포 때 법적 문제, 자동 검색이 권리가 불분명한 자료를 고를 위험, 원 출처의 핫링크 차단·영상 삭제, 외부 플레이어의 추적·광고 |
   | 줄이는 장치 | 안전장치 1~6, 공식 채널만(M3-P14), 정확도 기준선(M3-P11), 로컬 데모만(#5 (a)), 비상업(#1 (a)) |
   | 다시 볼 때 | 공개 배포를 정할 때(M6 끝), 권리자 요청을 받았을 때, 상업화를 검토할 때 |

5. **자동 검색의 정확도·쿼터, 그리고 국내 영상 공백** — 엉뚱한 영상(이름만 같은 다른 사건, 기념·재현 영상)이 붙을 수 있고, YouTube Data API 쿼터가 하루 요청 수를 제한한다. **리서치 T1: 국내 날짜에는 Commons 영상이 없어 데모 날짜 영상은 YouTube 키(M3a5)에 달려 있다.** 대응: 정확도 규칙과 기준선, 표본 날짜 PM 품질 확인과 기준표, 차단 목록, 사건 3개 제한(M3-P12), 결과 캐시(0건 포함), 쿼터 상한 80%, PM 키 발급을 리서치 머지 직후로. 촬영 시점이 명시되지 않은 영상은 "촬영 시점 미상"으로 정직하게. `tragic` 사건·날에는 영상을 찾지 않는다.
6. **예상보다 큰 PR과 응답 지연** — M3a1·M3b1 실제 줄 수가 예상의 1.6~1.75배였다. 대응: 남은 계획서의 분할 기준을 낮추고 M3a1 옮긴 작업을 둘로 나눴다. 응답 지연은 위키백과 날짜당 상한(M3a1c), 동시 요청 3개(M3a1b), M6b 측정. 영상 데이터 사용량·모바일 성능은 보일 때만 재생, 동시에 하나, 작은 해상도 먼저, 지연 로딩, 데이터 절약·움직임 줄이기면 자동 재생 안 함(M3-P8).
