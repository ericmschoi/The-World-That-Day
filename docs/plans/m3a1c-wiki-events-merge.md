## 목표

1. `KoWikiEventSource.find(LocalDate)` 가 날짜 문서·연도 문서의 그날 사건을 합치고 **같은 사건은 한 번만** 남겨, 사건 목록, 문서별 판 번호, 문서 상태를 돌려준다. M3a2가 이 계약을 그대로 쓴다.
2. 사건의 링크를 정규 제목(넘겨주기 해석)과 Wikidata QID로 바꿔 둔다. 중복 제거에 쓰고, M3a2가 QID를 다시 묻지 않게 넘긴다(원래 M3a2의 pageprops 조회를 이 기능으로 옮김).
3. 날짜 하나를 처리하는 시간이 상한(`wikimedia.kowiki-day-deadline`)을 넘지 않는다. DB가 닿지 않아도 넘지 않는다(T1b, T4).

## 설계

### 불변 조건 — 맞는 문서만 파서에 넣는다 (검증 3)

`WikitextEventParser` 는 날짜 문서에서는 연도만, 연도 문서에서는 월·일만 맞춰 본다. 그래서 **`KoWikiEventSource` 는 늘 `KoWikiPageKind.title(date)` 로 고른 두 문서만** 파서에 넘기고, 파서에 넘기는 "찾는 날짜"는 요청 날짜 그대로다. 다른 경로로 문서 제목을 만들지 않는다.

### 날짜당 시간 상한 (리뷰 2)

| 규칙 | 내용 |
|---|---|
| 상한 | `wikimedia.kowiki-day-deadline: 5s` — 문서 두 개와 pageprops 요청 전체. 남은 시간을 각 호출의 상한으로 넘긴다(읽기 타임아웃보다 남은 시간이 짧으면 남은 시간) |
| 날짜 문서가 시간 초과 | 같은 호스트가 멈춘 것으로 보고 **연도 문서를 요청하지 않는다**(캐시가 있으면 캐시는 쓴다). 날짜 문서 상태 `UNAVAILABLE`, 연도 문서는 캐시가 있으면 `STALE`, 없으면 `UNAVAILABLE` |
| 상한 도달 | 그때까지 받은 문서로 결과를 만든다. 남은 문서는 `UNAVAILABLE`(캐시가 있으면 `STALE`). pageprops를 못 하면 `linkResolutionFailed` |
| DB가 닿지 않을 때 | 캐시 호출 하나의 DB 대기는 Hikari `connection-timeout` 1초가 위 한도(T1b). 날짜당 DB 대기는 T1b 뒤 최대 4번(약 4초), T4 뒤 **최대 2번(약 2초)** — 나머지 시간은 위키백과 요청에 남는다 |
| 근거 | 제품 정의서 8절: 느린 섹션은 나중에 채우고 전체 10초 목표. 세계 섹션의 나머지(Wikidata, Commons)가 쓸 시간을 남긴다. 값은 M6b 측정으로 보정 |

### DB 오류 때 캐시 쓰기 건너뛰기 (2026-10-12 PM 결정 2, T4)

`CachingKoWikiClient.fetch(title)` 한 번 안에서, 캐시 읽기가 DB 오류(`DataAccessException`·`TransactionException`)로 실패했으면 그 문서의 캐시 쓰기를 하지 않는다. DB가 닿지 않으면 쓰기도 같은 시간을 기다린 뒤 실패할 뿐이기 때문이다. 다른 동작은 그대로다.

| 캐시 읽기 결과 | 위키백과 결과 | 동작 |
|---|---|---|
| 행 있음, 유효 | (요청 안 함) | `CACHED` — 그대로 |
| 행 있음, 만료 | `FRESH` / `UNAVAILABLE` / `ABSENT` | upsert 후 `FRESH` / 옛 행으로 `STALE` / 행 삭제 후 `ABSENT` — 그대로 |
| 행 없음 | `FRESH` / `UNAVAILABLE` / `ABSENT` | upsert 후 `FRESH` / `UNAVAILABLE` / 삭제 없이 `ABSENT` — 그대로 |
| **읽기 실패 (DB 오류)** | `FRESH` | **upsert 하지 않는다.** 돌려주는 페이지는 지금과 같다(`FRESH`, `fetchedAt` 마이크로초로 자름) |
| **읽기 실패 (DB 오류)** | `UNAVAILABLE` / `ABSENT` | `UNAVAILABLE` / `ABSENT`, DB 호출 없음 — 지금과 같다(행을 모르니 `STALE`·삭제 없음) |

- 로그: 읽기 실패 WARN 1줄(지금과 같음). 쓰기를 건너뛸 때 WARN을 더 남기지 않는다(DEBUG 1줄은 허용, 제목과 예외 클래스 이름만).
- "같은 호출"은 `fetch(title)` 한 번이다. 다음 요청은 다시 읽기부터 한다(실패 상태를 기억하지 않는다).
- `cached(title)`(날짜 문서 시간 초과 때 연도 문서) 는 원래 읽기만 하므로 바뀌지 않는다.

### 링크 정규화와 QID (검증 2)

1. 사건마다 링크 제목을 정규화한다: 밑줄 → 공백, `#절` 제거, 앞뒤·연속 공백 정리, 첫 글자가 라틴 문자면 대문자(MediaWiki 제목 규칙).
2. 그날 사건들의 모든 링크 제목을 모아 pageprops 요청으로 **넘겨주기·정규화 결과**와 **`wikibase_item`(QID)** 을 받는다. 사건의 `linkTitles` 는 해석된 정규 제목으로 바꾸고, 대표 링크의 QID를 `wikidataQid` 에 담는다. 사건이 없거나 링크가 없으면 요청하지 않는다.
3. 두 링크가 같은지: QID가 둘 다 있고 같거나, 해석된 제목이 같거나, 글자 열쇠(해석된 제목에서 맨 앞 `(\d{4})년 ` → `$1 `)가 같으면 같은 링크다.
4. 연도 문서·날짜 문서 링크(`^\d+년$`, `^\d+월 \d+일$`)는 비교 집합에서 뺀다.
5. pageprops 요청이 실패하면 1·3의 글자 정규화만으로 비교하고, 모든 `wikidataQid` 는 `null`, 결과 `linkResolutionFailed` = true(→ `degraded()` true → M3a2 `partial`).
6. 화면 문장(`text`)은 바꾸지 않는다(#23 (a)). 정규화는 비교와 링크 주소에만 쓴다.

### 중복 제거 (검증 1·2로 바꾼 규칙, 2026-10-12 D3 보정)

입력은 네 절(날짜 문서 사건 → 문화 → 연도 문서 사건 → 문화)의 그날 사건, 이 순서. "일반 링크"는 나라·도시처럼 여러 사건에 두루 붙는 링크로, 서버 리소스 파일 `kowiki-generic-links.txt`(처음 값: 녹화 fixture 12개 절에 나온 나라·도시 링크 — T2 보고서에 목록)와 4항의 연도·날짜 문서다. **"구체 링크"는 일반 링크도, 연도·날짜 문서 링크도 아닌 링크**다. **"목록 일반 링크"는 `kowiki-generic-links.txt` 에 있는 링크만**이다(연도·날짜 문서 링크는 넣지 않는다 — 아래 D3 일반 링크 충돌에만 쓴다).

| 규칙 | 내용 |
|---|---|
| D1 같은 절은 합치지 않는다 | 편집자가 한 절에 따로 적은 줄은 다른 사건으로 본다(같은 날 같은 대회의 여러 경기 등). **예외(T2 편차)**: 사건 ID가 같은 두 줄(같은 문서·같은 평문)은 같은 절이어도 하나로 합친다 — ID가 겹치지 않게 하려는 것. 로그 규칙 이름은 D2 |
| D2 글자 일치 | 공백·문장부호를 정리한 `text` 가 같으면 같은 사건 |
| D3 공유 대표 링크 + 겹침 (**2026-10-12 보정, T4**) | 아래 세 조건을 모두 만족하면 같은 사건. (i) 두 사건 중 하나의 대표 링크 L이 구체 링크이고 다른 사건의 링크 집합에도 있다. (ii) 두 사건의 **구체 링크 집합**의 겹침 계수가 `wikimedia.dedup.min-link-overlap`(0.6) 이상이다. **겹침 계수 = 공유 구체 링크 수 ÷ 큰 쪽 구체 링크 수.** 집합 안에서 같은 링크(위 3항)는 하나로 센다. (iii) **일반 링크 충돌이 없다** (PM 결정 3): 두 사건이 **모두** 목록 일반 링크를 하나 이상 가지고 있는데 그 목록 일반 링크가 **하나도 겹치지 않으면**(같은 링크 판단은 위 3항) 합치지 않는다. 한쪽이라도 목록 일반 링크가 없거나 하나라도 겹치면 (iii)은 막지 않는다. 예: 연도 문서 문화 하위 줄(대표 링크 `대한민국`, 링크 `대한민국`·`서울특별시`·`1988년 하계 올림픽`)의 구체 링크는 `1988년 하계 올림픽` 하나라 날짜 문서 사건 줄(`1988년 하계 올림픽`, 목록 일반 링크 없음)과 1 ÷ 1 = 1.0으로 합쳐진다. (T2 원래 규칙: 일반 링크까지 센 링크 집합, 작은 쪽 분모, (iii) 없음) |
| D4 일대일 | 뒤 절의 사건 하나가 앞 절의 서로 다른 사건 둘 이상과 맞으면 **합치지 않는다**(애매하면 사건을 잃지 않는 쪽) |
| D5 남는 쪽 | 묶음에서 입력 순서가 가장 앞인 것(날짜 문서 사건 > 문화 > 연도 문서 사건 > 문화)을 남긴다. 남은 사건의 문장·출처·판 번호는 바꾸지 않는다(문장을 섞지 않음) |
| D6 기록 | 뺀 사건 수를 `mergedCount` 에 담는다. DEBUG 로그에는 규칙 이름(D2/D3/D4)과 **사건 ID의 해시 8자리만**(문장·날짜·전체 ID는 남기지 않음, T2 편차) |

- 사건 ID: `kowiki-{yyyy-MM-dd}-{SHA-256(문서 제목 + "\n" + 평문) 앞 8자리 16진수}`. 같은 판이면 매번 같다.
- `skippedLines` 는 두 문서의 건너뛴 줄 수의 합.
- 겹침 기준값은 설정값이다. T2가 0.6을 골랐고 T4에서도 0.6을 쓴다(아래 범위 안). 데모 날짜에 맞춘 특수 처리를 하지 않는다.

#### D3 보정 규칙을 고른 이유 (PM 결정 1·3)

세 가지 사례를 녹화 fixture(`server/src/test/resources/fixtures/wikimedia/kowiki/`)와 기존 테스트(`KoWikiEventDeduplicatorTest`, `KoWikiEventMergeAcceptanceTest`)에서 확인했다. 아래 "구체 집합"은 일반 링크·연도/날짜 링크를 뺀 링크, "목록 일반"은 목록 일반 링크다.

| 사례 | 줄 (절) → 구체 집합 / 목록 일반 | (가) 큰 쪽 분모 | (나) 작은 쪽 1개면 공유 2개 이상 | (iii) 일반 링크 충돌 |
|---|---|---|---|---|
| 데모 1988-09-17 개막 ×4 | 날짜 사건 `{1988년 하계 올림픽}` / 없음, 날짜 문화 `{1988년 하계 올림픽}` / `{대한민국, 서울}`, 연도 사건 `{1988년 하계 올림픽}` / 없음, 연도 문화 하위 줄 `{1988년 하계 올림픽}` / `{대한민국, 서울특별시}` | 1/1 = 1.0 → **3줄 합쳐짐 (통과)** | 작은 쪽 1개, 공유 1개 → **안 합쳐짐 (실패)** | 날짜 사건·연도 사건은 목록 일반 없음, 날짜 문화와 연도 문화 하위 줄은 `대한민국` 공유 → **막지 않음 (통과)** |
| 데모 2002-06-22 스페인 ×2 | 날짜 문화 `{2002 FIFA 월드컵}` / 없음, 연도 문화 `{2002년 FIFA 월드컵}` / 없음 (본문의 나라 이름은 링크가 아님) | 1/1 = 1.0 → **1줄 합쳐짐 (통과)** | **안 합쳐짐 (실패)** | 목록 일반 없음 → **막지 않음 (통과)** |
| 재현 (T3) | 앞 `{2002 시험 대회}`, 뒤 `{2002년 시험 대회, 시험 팀 다, 시험 팀 라}` / 둘 다 없음 | 1/3 ≈ 0.33 → **2개 (통과)** | 2개 (통과) | 해당 없음 (통과) |
| 반례 "시험 대회 A조 경기 가/나/다" | `{시험 대회, 시험 팀 가}`, `{시험 대회, 시험 팀 나}`, `{시험 대회, 시험 팀 다, 시험 팀 라}` / 모두 없음 | 1/2, 1/3 → **따로 (통과)** | 따로 (통과) | 해당 없음 (통과) |

→ **(가) 큰 쪽 분모 + (iii) 일반 링크 충돌을 쓴다.** (나)는 데모 두 묶음이 모두 "양쪽 구체 링크 1개, 공유 1개"라 데모를 깨뜨린다. (가)는 두 줄 **모두**에서 공유 링크가 차지하는 몫을 재므로, 구체 링크가 하나뿐인 짧은 줄이 링크가 많은 줄을 "흡수"하지 못한다. 기준값 0.6이 맞는 범위: 반례(1/2)를 가르려면 0.5 초과, 기존 `d3SharedMainLinkWithEnoughOverlapMerges`(2/3)를 합치려면 2/3 이하 → 0.6 그대로.

(가)만 쓰면 일반 링크를 집합에서 빼므로, 구체 링크 하나만 같고 나머지가 모두 일반 링크(나라 이름 등)인 두 줄은 다른 사건이어도 1.0으로 합쳐진다(예: 같은 대회에서 서로 다른 나라끼리 치른 두 경기를 나라 문서 링크로만 적은 두 줄). (iii)이 이 경우를 막는다(PM 결정 3) — "해결된 것" 참고. (iii)은 "막기만" 하는 조건이라 새로 합쳐지는 경우는 생기지 않는다.

(가)로 바뀌는 점 (리스크 1에 반영): 앞 줄 `{X}`, 뒤 줄 `{X, Y}` 는 1/2 = 0.5로 **더 이상 합쳐지지 않는다**(T2 규칙에서는 합쳐짐). 같은 사건을 장소 링크 하나 더 붙여 적은 줄은 두 번 보일 수 있다 — 사건을 잃는 것보다 덜 나쁜 실패.

기존 테스트 중 **입력을 바꿔야 하는 것** (규칙은 그대로 시험하고 단언은 지우거나 약하게 하지 않는다):
- `KoWikiEventDeduplicatorTest.d4LineMatchingTwoEarlierEventsIsNotMerged` — 지금 입력(`{가}`, `{나}`, 뒤 줄 `{가, 나}`)은 (가)에서 1/2라 어느 쪽과도 맞지 않아, 테스트는 통과하지만 **D4 경로를 타지 않는다**. 뒤 줄이 앞 줄 둘과 모두 0.6 이상 맞는 입력으로 바꾼다(예: `{가, 나, 다}`·`{가, 나, 라}` 와 뒤 줄 `{가, 나}` → 2/3, 2/3).
- `KoWikiEventDeduplicatorTest.debugLogsNameTheRuleAndIdHashButNoTextOrDate` 의 D4 줄 — 같은 이유로 `rule=D4` 가 나오지 않아 실패한다. 위와 같은 꼴로 바꾼다.
- `KoWikiEventDeduplicatorTest.d5TheFirstLineIsKeptUnchanged` — 셋째 줄 `{시험 대회, 시험 장소}` 가 1/2로 따로 남아 실패한다. 셋째 줄이 (가)에서도 같은 사건이 되는 링크(예: `대한민국`, `시험 대회`)로 바꾼다.
- `KoWikiEventMergeAcceptanceTest`(T3)와 나머지 D1~D3 테스트는 손대지 않고 통과해야 한다(위 표로 확인. 기존 D3 테스트에서 두 줄이 모두 목록 일반 링크를 가진 경우는 `mergedCountIsTheNumberOfRemovedLines` 의 `{시험 대회, 대한민국}`·`{대한민국, 시험 대회}` 처럼 `대한민국` 을 공유하므로 (iii)에 걸리지 않는다).

### M3a2에 넘기는 인터페이스 (계약)

```java
public interface KoWikiEventSource {
  KoWikiDayResult find(LocalDate date);
}

public record KoWikiDayResult(
    LocalDate date,
    List<KoWikiEvent> events,        // 입력 순서, 중복 제거 후
    List<KoWikiDocStatus> docs,      // 날짜 문서, 연도 문서 순서로 2개

    int mergedCount,                 // 중복으로 뺀 사건 수
    boolean linkResolutionFailed) {  // pageprops 요청 실패·시간 상한
  public boolean allUnavailable() { ... } // 두 문서 모두 UNAVAILABLE
  public boolean degraded() { ... }       // 하나라도 UNAVAILABLE 또는 STALE, 또는 linkResolutionFailed
}

public record KoWikiEvent(
    String id,                // kowiki-1988-09-17-1a2b3c4d
    LocalDate date,
    String sourceTitle,       // "9월 17일" 또는 "1988년"
    String sourceSection,     // "사건" 또는 "문화"
    long revision,
    String text,              // 평문 (원문 그대로, 링크 기호 등만 제거)
    List<String> linkTitles,  // 해석된 정규 제목. 첫 번째가 대표 링크. 없으면 빈 목록
    String wikidataQid,       // 대표 링크의 QID. 없거나 해석 실패면 null

public enum DocState { FRESH, CACHED, STALE, ABSENT, UNAVAILABLE }  // CACHED·STALE은 M3a1b
```

이름은 바꿔도 되지만 필드의 뜻과 `allUnavailable`·`degraded` 의 정의는 지킨다. 바꾸면 보고서에 적는다. M3a1·M3a1b에서 만든 형은 그대로 쓴다. T4는 이 계약을 바꾸지 않는다.

## 테스트 방침

M3a1 계획서 "테스트 방침"을 따른다. 추가:

- **녹화 fixture**: 데모 날짜 사건 링크의 pageprops 응답(`fixtures/wikimedia/kowiki/pageprops-*.json`), `README.md` 에 원 URL·녹화 일자·라이선스. 녹화는 M3a1 T2와 같은 방식(공개 User-Agent, `curl`). 네트워크를 쓸 수 없으면 "막힘"으로 보고하고 PM이 실행할 `curl` 명령을 적는다.
- **반례 합성 fixture**: 중복이 아닌데 합쳐질 수 있는 경우를 중립 문장으로(예: "시험 대회 A조 경기 가"·"시험 대회 A조 경기 나"가 같은 대회 링크만 공유). 실제 사건·인물을 지어내지 않는다. T4·T5의 재현·일반 링크 충돌 사례도 같은 방식(링크 `2002 시험 대회`, `시험 팀 다` 등. 나라 링크는 목록에 이미 있는 제목만 쓰고, 실제 경기 결과처럼 읽히지 않는 중립 문장으로)으로 만든다.
- 시간 상한은 작은 테스트 값(예: 상한 1초, 읽기 타임아웃 300ms)과 WireMock 지연으로 시험한다.
- DB 오류는 저장소 mock이 `CannotCreateTransactionException`·`DataAccessResourceFailureException` 을 던지게 하거나(연결 풀 고갈·DB 다운 모사), 기존 `CachingKoWikiClientDatabaseDownTest` 처럼 Testcontainers 컨테이너를 멈춰 시험한다.
