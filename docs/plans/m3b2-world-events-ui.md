# 그날의 세계 섹션 (M3b2)

> 브랜치: `feat/world-events-ui` · 작성: planner · 상태: PM 승인 (2026-10-11, 미디어 결정 반영 개정) · **2026-10-11 갱신: 선행에 M3b1b 추가, 촬영 시점 미상 사진 묶기(M3-P17 (a), 결정 2026-10-11), 서버 DTO 대조**
> 기준: `docs/product-brief.md` 5절 4번·6절·8절·12절, `CLAUDE.md` 7절 1항(**촬영 시점을 모르면 "촬영 시점 미상"으로 표시하고 그날 것처럼 보이게 하지 않는다** — PM 결정 2026-10-11), `docs/roadmap.md` M3, `docs/plans/m3a2-world-events-api.md`("API 계약"), `docs/plans/m3a3-event-media.md`("공용 미디어 형식", "촬영 시점 미상 규칙"), `docs/plans/m3b1-design-foundation.md`(토큰·문구), `docs/plans/m3b1b-media-card.md`(카드)
> 선행: M3a3 `feat/event-media`, M3b1 `feat/design-foundation`, **M3b1b `feat/media-card`** 머지. (자동 테스트는 MSW라 서버가 없어도 되지만, PM 화면 확인에 실제 사진이 필요해 M3a3 머지를 기다린다.) 영상·제공사 임베드는 이 기능 뒤 M3b3 `feat/media-video` 가 같은 `MediaItem` 에 붙인다 — 이 섹션 코드는 바꿀 필요가 없다.

## 목표

1. 결과 화면의 `world` 섹션이 `GET /api/story/world` 를 불러 그날의 사건을 보여 준다: 원문 문장, 사건 미디어(바로 표시), 문장 출처(위키백과 문서 링크 + CC BY-SA 4.0, #23 (a)).
2. 같은 날 찍힌 사진(`day_media` 중 `same_day`)을 "그날 찍힌 사진"으로 보여 준다. 촬영 시점을 확인하지 못한 사진은 **그 제목 아래에 두지 않는다**(M3-P17).
3. `tragic` 사건은 정상 사건 뒤에 차분한 별도 블록으로, 미디어 없이 보여 준다(제품 정의서 6.3절).
4. 사건이 없는 날은 "이 날짜에 기록된 큰 사건을 찾지 못했습니다."를 보여 주고 섹션을 숨기지 않는다(#21 (a)).
5. 요청이 실패하거나 10초 안에 끝나지 않으면 이 섹션만 오류 상태가 되고 다른 섹션은 그대로다(제품 정의서 8절).
6. 입력 화면이 생기기 전(M2b)까지 PM이 실제 서버로 데모 3개 날짜를 볼 수 있게 **임시 데모 날짜 버튼**을 둔다(M3-P5 (a), 결정).

## 범위 밖

- 영상·제공사 임베드 재생 → M3b3 (이 섹션은 `MediaItem` 에 미디어를 넘기기만 한다)
- 실제 입력 폼, 날짜 검증 문구, 오프닝, 결과 화면 URL, 화면 전환 포커스 이동 → M2b (M2b가 임시 데모 버튼을 지운다)
- 장 전환 효과, 빈 섹션 문구 전체 다듬기, 출처 전체 목록 → M6a·M6b
- `scope` 로 국내·세계를 나눠 보여 주는 것
- 데이터 패칭 라이브러리
- 서버 변경

## 사용할 외부 출처

없음. 프론트엔드는 우리 API(`/api/story/world`)만 부른다. 사진은 데이터의 `thumbnail_url`(원 출처)에서 브라우저가 바로 받는다(안전장치 1, M3b1b `MediaFigure`).

## API / 데이터 계약 (서버 변경 없음)

`GET /api/story/world?date=YYYY-MM-DD` — 응답·에러 형식은 `docs/plans/m3a2-world-events-api.md` "API 계약", 미디어는 `docs/plans/m3a3-event-media.md` "공용 미디어 형식"이 원천이다. 프론트엔드 타입(`web/src/world/types.ts`)은 그 표와 이름·형이 같다(snake_case 그대로, 미디어 타입은 M3b1 `web/src/media/types.ts` 를 쓴다). **M3a3 머지 뒤 실제 서버 DTO(M3a3 T4 보고의 필드 목록)와 `web/src/media/types.ts` 를 대조**해 다르면 T1에서 웹 타입을 고친다(M3b1 T2 메모).

| 응답 | 화면 |
|---|---|
| 200, `events` 있음 | `ready` — 정상 사건 목록 → "그날 찍힌 사진"(있으면) → 촬영 시점 미상 사진 묶음(있으면, M3-P17) → 비극 블록(있으면) |
| 200, `notice.code` = `NO_EVENTS_FOUND` | `ready` — 안내 문장 + "그날 찍힌 사진"(있으면) + 촬영 시점 미상 묶음(있으면) |
| 200, `partial` = `true` | 위와 같음 (화면 표시 없음) |
| 400, 503, 네트워크 오류, 10초 시간 초과 | `StorySection` `error` ("이 섹션을 불러오지 못했습니다.") |
| 요청 중 | `StorySection` `loading` |

### `day_media` 묶기 (M3-P17 — (a) 결정 2026-10-11)

서버는 `day_media` 를 `same_day` 먼저, `unknown` 은 맨 뒤 순서로 보낸다(M3a3). Commons "그날 찍은 사진" 범주에서 왔지만 파일 자체의 촬영 시점을 읽지 못한 사진이 있다(1988-09-17 데모에 1장).

| 선택지 | 화면 | 메모 |
|---|---|---|
| **(a) 결정** | "그날 찍힌 사진" 제목 아래에는 `date_relation.kind = same_day` 만. 나머지(`unknown` 등)는 그 아래 별도 소제목 **"촬영 시점을 확인하지 못한 사진"** 아래에 각자 캡션("촬영 시점 미상" 등)과 함께 | 제목이 사진의 날짜를 보증하지 않는다. 결정 문구("그날 찍은 것처럼 보이게 하지 않는다")에 가장 가깝다. 약 10줄 |
| (b) | 한 묶음으로 두고 제목을 "이 날짜로 분류된 사진"으로 바꾼다. 카드마다 자기 배지·문구 | 단순하지만 "분류"라는 말이 낯설고, 같은 날 사진의 감동이 약해진다 |
| (c) | 촬영 시점 미상 사진은 `day_media` 에서 보여 주지 않는다 | 결정("보여 준다")과 어긋난다. 비추천 |

이하 계획은 (a) 기준이다.

### API 클라이언트 보강 (M1 리뷰에서 M2b 몫으로 미뤘던 것을 당김)

- `apiGet<T>(path, options?: { signal?: AbortSignal; timeoutMs?: number })`. `timeoutMs` 기본 10000(제품 정의서 8절).
- 호출자의 `signal` 과 시간 초과 신호를 합쳐(`AbortSignal.any` + `AbortSignal.timeout`) `fetch` 에 넘긴다.
- 시간 초과 → `ApiTimeoutError`. 호출자가 취소 → 원래 `AbortError` 그대로(컴포넌트는 무시).
- `getWorld(date: string, signal?: AbortSignal)` → `/api/story/world?date=` + `encodeURIComponent(date)`. 기존 `/api/` 경로 검사는 쿼리가 붙어도 통과해야 한다.
- 기존 `getHealth()` 동작과 테스트는 그대로.

### 화면 구조와 문구

```

 ┌ 사건 ───────────────────────────────┐
 │ 제24회 서울 하계 올림픽 개막.            │  ← summary 원문 그대로
 │ [MediaItem × 사건 media 개수]          │  ← 바로 표시 (M3b3 뒤에는 영상도)
 │ 출처: 한국어 위키백과 「9월 17일」 ·       │  ← 문서 링크(source_url) + 라이선스 링크
 │       CC BY-SA 4.0                    │     (text_license_url)
 └─────────────────────────────────────┘
 그날 찍힌 사진                            (h3, same_day 사진이 있을 때)
   [MediaItem × N]
 촬영 시점을 확인하지 못한 사진              (h3, 그 밖의 day_media 가 있을 때 — M3-P17 (a))
```

|---|---|
| 빈 날짜 안내 | 이 날짜에 기록된 큰 사건을 찾지 못했습니다. |
| 그날 사진 소제목 | 그날 찍힌 사진 |
| 촬영 시점 미상 묶음 소제목 | 촬영 시점을 확인하지 못한 사진 |
| 비극 블록 소제목 | 같은 날 있었던 아픈 일 |

- 사건 카드 안의 미디어가 `unknown` 이면 카드 캡션에 "촬영 시점 미상"(M3b1b)이 그대로 보인다. 사건 문장이 그날 일이라는 이유로 사진을 그날 사진처럼 설명하지 않는다(대체 텍스트에도 날짜를 넣지 않는다).
- 비극 블록에는 강조색·축하 요소·미디어를 쓰지 않는다. `tragic` 사건에 `media` 가 와도(서버 규칙상 오지 않음) 그리지 않는다.

### 임시 데모 날짜 버튼 (M2b가 지움)

- 입력 화면의 "빈 결과 화면 보기" 버튼을 데모 날짜 버튼 3개로 바꾼다: "1988년 9월 17일로 보기", "2002년 6월 22일로 보기", "1995년 3월 15일로 보기". 제품 정의서 12절 데모 날짜만 쓴다.
- `App` 상태는 `{ screen: 'input' } | { screen: 'story', date: string }`. `StoryScreen` 이 `date` 를 받아 `world` 섹션에만 넘기고 나머지 4개 섹션은 `empty`.
- "처음으로" 로 돌아오면 진행 중이던 요청은 취소된다.
- 날짜를 URL·`localStorage` 에 넣지 않는다(결과 URL 설계는 M2b, 개인정보).

## 테스트 방침

M1b "테스트 방침"을 따른다. 추가:
- MSW 응답은 `web/src/mocks/fixtures/world/` 의 데모 3날짜 JSON(M3a2·M3a3 계약 모양, 내용은 데모 기대값). 1988 fixture에는 `same_day` 사진과 `unknown` 사진을 함께 둔다. 핸들러는 `date` 쿼리로 고른다.
- 비극 블록 시험용 응답은 테스트 파일 안에서 만들고 문장은 "시험용 비극 사건 문장"처럼 누가 봐도 가짜로 쓴다. 개발용 목에는 넣지 않는다.
- **effect 요청 테스트는 끝을 기다린다** (M1 리뷰 권장): 마지막 화면 상태를 `findBy*`/`waitFor` 로 확인한 뒤 끝낸다(C3).
- 시간 초과는 작은 `timeoutMs` 를 주입하거나 가짜 타이머로 시험한다.

## 크기 (400줄 규칙)

예상: 클라이언트 보강 약 30, 타입 약 35, `WorldSection` 약 70, 사건 항목·출처 줄 약 45, 비극 블록 약 30, 그날 사진·미상 묶음 약 30, 입력 화면·`App`·`StoryScreen` 약 35, CSS 약 60 → **약 335줄**. M3b1 T2가 예상의 약 1.75배였으므로 **T2 뒤 누적 250줄을 넘으면** T3(데모 버튼·화면 연결)을 따로 뺄지 PM에게 묻는다.
