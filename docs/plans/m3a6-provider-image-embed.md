# 제공사 공식 이미지 임베드 자동 검색 (M3a6) — **M3에서 제외**

> 브랜치: `feat/provider-image-embed`(만들지 않음) · 작성: planner · 상태: **M3에서 제외 (PM 결정 2026-10-11, `docs/research/video-sources.md` 10.1절 15번 G-D1 (a))**. 공개 배포(#5)를 정할 때 다시 본다. 아래 "원래 계획"은 기록으로 남긴다.

## 제외한 이유

- M3-P15(2026-10-11): 리서치가 자동 검색 경로와 비상업 조건을 "확인됨"으로 만들지 못하면 이 기능을 뺀다.
- 리서치 V6 결과(3.4절, 9절): 게티 공식 임베드는 운영 중이고 비상업 웹사이트에 허용된다(**확인됨**). 그러나 **자동 검색 API 키는 게티 영업 담당자와 계약해야만 나온다**(셀프 발급 없음, "계약 대기"). 키 없는 경로는 사이트 긁기(약관상 금지)나 사람이 고른 자산 ID(M3-P9 (b) "아무 날짜에서나 자동"과 맞지 않음)뿐이다.
- AP·로이터·연합뉴스는 공식 임베드를 확인하지 못했다(미확인, 10.1절 20번 — PM의 G-B3 확인 뒤 재조사).

## 이 결정이 바꾼 것

| 자리 | 바뀐 것 |
|---|---|
| M3a4 | `selection.basis` 에서 `provider_embed` 를 뺐다. "제공사 이미지 임베드 최대 1" 규칙을 뺐다 |
| M3a3 | `media.allowed-image-embed-providers` 는 빈 목록 그대로. `image_embed` 형식(R3)은 남겨 둔다(M4·M5·다시 열 때) |
| M3b3 | `ImageEmbedFrame` 을 만들지 않는다. `MediaItem` 은 `image_embed` 를 그리지 않는다 |
| 로드맵 | M3 기능 목록·PR 수·PM 작업에서 뺐다. 후속 작업 후보 "공개 배포 때 게티 계약 문의"로 옮겼다 |
| 안전장치 3 | 그대로다: 통신사·언론사 사진은 공식 임베드로만. M3에서는 그런 경로가 없어 통신사 사진을 보여 주지 않는다 |

## 다시 열 때 고칠 것 (리서치 9절·7절에서)

1. 키: `GETTY_API_KEY` 는 PM이 콘솔에서 만들 수 없다 — 게티 영업에 테스트 계정·계약을 문의한다(리서치 6.4절 문의 항목 5개). 받으면 G1~G3 실행 → "확인됨".
2. 검색: `GET /v3/search/images/editorial` + `embed_content_only=true` + `date_from`=`date_to`=사건 날짜(R-G2, 연도 검색 대신).
3. 임베드 주소: 게티 서명(`sig`) 때문에 서버가 자산 ID만으로 만들 수 없다. 자산마다 oEmbed(`uri_oembed`) 1회, 200이고 `sig` 가 있을 때만(R-G3). iframe 주소를 서버가 조립(10.1절 18번 G-D4 (a)).
4. 날짜: `date_camera_shot` 우선, 캡션에 같은 날짜가 있을 때만 `day`, `date_created` 가 `YYYY-01-01` 이면 `null`(R-G1). 기념 배포 제목은 M3a4 기념어 감점(R-G4).
5. 사건어: 영어 라벨로 대조, 영어가 아닌 캡션은 맞지 않으면 붙이지 않음(R-G5). 출처 제외 목록은 `image_embed` 에 적용하지 않음(R-G7). `tragic` 은 찾지 않음(R-G6).
6. 결정 기록(지금은 적용하지 않음): G-D2 (a) "편집 목적"에 해당한다고 보고 진행 + 공개 전 서면 문의, G-D3 (b) 서버의 oEmbed 자동 호출은 계약 때 서면 확인, G-D4 (a), G-D5 (a) 캡션은 짧은 제목·작가·컬렉션만.
7. 웹: `ImageEmbedFrame`(`scrolling="no"`, 비율 상자, 덮개 없음). iframe 안 실패를 알 방법이 없어 서버 단계에서만 거른다. 뷰어의 광고·추적은 개인정보처리방침 (f)·(g)에 더한다(M3b3b).
8. 공개 배포 판단(#5)과 함께 본다: 상업 이용 금지 조항, 게티가 뷰어에서 이미지를 뺄 권리, `sig` 만료(G-B2).

## 원래 계획 (2026-10-11 승인안 — 진행하지 않음)

> 기준: 안전장치 3 개정(통신사·언론사 사진은 제공사 공식 임베드로만), M3-P9 (b), `docs/plans/m3a4-event-video.md`(검색 틀·정확도 규칙), `docs/plans/m3a3-event-media.md`(`image_embed` 형식, R3), `docs/plans/m3-video-sources-research.md` V6, `CLAUDE.md` 7절 2·4항
> 조건부: 리서치 V6에서 게티이미지(또는 다른 통신사)의 공식 임베드가 운영 중이고, 자동 검색 경로(검색 API와 "임베드 가능" 표시)와 비상업 웹사이트 이용 조건이 "확인됨"일 때만 진행한다. 아니면 이 기능은 M3에서 빠진다(M3-P15).

### 목표

M3a4 검색 틀에 제공사 공식 이미지 임베드 어댑터(처음은 게티이미지)를 붙인다. 사건마다 검색해 "임베드 가능"으로 표시된 이미지 중 정확도 규칙을 넘는 것 1개를 `image_embed`(`provider: getty`)로 붙인다. 이미지는 제공사 서버에서 제공사 로고와 함께 iframe으로 나오고, 우리 서버는 파일을 받지 않는다.

### 규칙

| 규칙 | 내용 |
|---|---|
| 검색 | 리서치가 확인한 검색 경로(키 이름 예 `GETTY_API_KEY`, 서버 전용)로 사건 대표 링크 제목 + 연도. 사건마다 1회, M3a4의 사건 3개 제한 안에서 |
| 임베드 가능 | 결과의 "임베드 가능" 표시가 있는 것만. 형식이 아니면 버림 |
| 정확도 | M3a4 정확도 규칙. 날짜는 캡션의 촬영일만. 없으면 `null` |
| 표시 값 | `license: provider-terms`, `license_status: other`, `source_name` 은 제공사 이름, `attribution` 은 제공사가 요구하는 문구, `selection.basis: provider_embed` |
| `tragic` | 찾지 않음 |
| 허용 제공자 | `media.allowed-image-embed-providers` 에 `getty` |
| 실패·키 없음 | 그 출처만 건너뜀. 키가 비면 어댑터 끔 |
