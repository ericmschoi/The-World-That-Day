# 제공사 공식 이미지 임베드 자동 검색 (M3a6, 조건부)

> 브랜치: `feat/provider-image-embed` · 작성: planner · 상태: PM 승인 (2026-10-11) (2026-10-11 M3-P9 (b)로 새로 생긴 기능)
> 기준: 안전장치 3 개정(통신사·언론사 사진은 제공사 공식 임베드로만), M3-P9 (b), `docs/plans/m3a4-event-video.md`(검색 틀·정확도 규칙), `docs/plans/m3a3-event-media.md`(`image_embed` 형식, R3), `docs/plans/m3-video-sources-research.md` V6, `CLAUDE.md` 7절 2·4항
> **조건부**: 리서치 V6에서 게티이미지(또는 다른 통신사)의 공식 임베드가 운영 중이고, **자동 검색 경로**(검색 API와 "임베드 가능" 표시)와 비상업 웹사이트 이용 조건이 "확인됨"일 때만 진행한다. 아니면 이 기능은 M3에서 빠진다(M3-P15).
> 선행: M3a4 머지(검색 틀) + 리서치 머지 + (키가 필요하면) PM 키 발급·확인 명령.

## 목표

M3a4 검색 틀에 **제공사 공식 이미지 임베드 어댑터**(처음은 게티이미지)를 붙인다. 사건마다 검색해 "임베드 가능"으로 표시된 이미지 중 정확도 규칙을 넘는 것 1개를 `image_embed`(`provider: getty`)로 붙인다. 이미지는 제공사 서버에서 제공사 로고와 함께 iframe으로 나오고, 우리 서버는 파일을 받지 않는다.

## 범위 밖

- 통신사 사진의 직접 표시·핫링크 (안전장치 3)
- 공식 임베드가 없는 통신사(리서치 결과)
- 웹 표시 (M3b3 `ImageEmbedFrame`)

## 규칙

| 규칙 | 내용 |
|---|---|
| 검색 | 리서치가 확인한 검색 경로(키 이름 예 `GETTY_API_KEY`, 서버 전용, PM 발급)로 사건 대표 링크 제목 + 연도. 사건마다 1회, M3a4의 사건 3개 제한 안에서 |
| 임베드 가능 | 결과의 "임베드 가능" 표시가 있는 것만. 임베드 주소는 리서치 문서의 공식 형식으로 서버가 만든다. 형식이 아니면 버림 |
| 정확도 | M3a4 정확도 규칙. 날짜는 캡션의 **촬영일**만(제공사 메타데이터에 있을 때). 없으면 `null` |
| 표시 값 | `license: provider-terms`, `license_status: other`, `source_name` 은 제공사 이름, `attribution` 은 제공사가 요구하는 문구(리서치), `selection.basis: provider_embed` |
| `tragic` | 찾지 않음 (보도 사진은 잔혹한 장면 위험이 특히 크다) |
| 허용 제공자 | M3a3 설정 `media.allowed-image-embed-providers` 에 `getty` 를 넣는다(리서치 "확인됨" 뒤) |
| 실패·키 없음 | 그 출처만 건너뜀. 키가 비면 어댑터 끔 |

## 리스크와 확인할 것

1. **조건부** — 리서치가 자동 검색 경로를 확인하지 못하면 진행하지 않는다.
2. **광고·추적** — 제공사 임베드에 광고나 추적이 들어갈 수 있다. 약관에 그런 조항이 있으면 리서치 T5에서 PM이 정한다.
3. **보도 사진의 장면** — `tragic` 이 아닌 사건에도 사고 장면이 있을 수 있다. PM 품질 확인과 차단 목록.
4. **저작권** — 공식 임베드라 낮지만 로드맵 리스크 4를 따른다.
