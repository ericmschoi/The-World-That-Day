# 개인정보처리방침과 동의 단계 (M3b3b)

> 브랜치: `feat/privacy-consent` · 작성: planner · 상태: **PM 승인 (2026-10-12)** (M3b3 분할로 새로 생김, 로드맵 D1 (a)·D2 (a))
> 기준: `docs/research/video-sources.md` 3.2절 V2 카드 "서비스 전체 의무"(YouTube API 개발자 정책 III.A.1, III.A.2 (a)~(g), III.F.2.a), 9절 5번, 8절 위험 E·26, 10.1절 9번 (a)(의무는 M3b3에서), **23번 (b)(입력 화면 안에서 제출 전에 필수 동의 + 개인정보처리방침 링크, PM 2026-10-11)**, `CLAUDE.md` 7절 6항(생년월일과 장소를 함께 남기지 않음), 제품 정의서 8절
> 선행: M3b2 머지(임시 입력 화면). M3b3과 서로 다른 파일이라 병렬 가능(둘 다 `InputScreen` 을 고치므로 기본은 M3b3 다음).
> 뒤따르는 기능: M3b3c(YouTube 플레이어)는 이 기능의 동의 상태가 있어야 YouTube 영상을 그린다. M2b가 동의 구성 요소를 실제 입력 폼 제출 버튼 앞으로 옮긴다.

## 왜 M2b가 아니라 지금인가 (로드맵 D2 (a), PM 결정 2026-10-12)

23번 결정은 "입력 화면 안에서 제출 전 필수 동의"다. 그런데 진행 순서는 M3 → M2라서 실제 입력 폼(M2b)보다 YouTube 영상(M3b3c)이 먼저 화면에 나온다. 10.1절 9번은 "의무가 갖춰지기 전에는 YouTube 영상을 보여 주지 않는다"고 정했다. 그래서 PM 결정(D2 (a))대로 동의 구성 요소와 방침을 지금 만들어 **임시 입력 화면(데모·표본 버튼) 안**에 두고, M2b가 같은 구성 요소를 실제 폼으로 옮긴다.

## 목표

1. **개인정보처리방침** 페이지를 만든다(III.A.2 (a)~(g) 내용, 한국어). 모든 화면 바닥글에서 늘 열 수 있다.
2. 입력 화면 안에 **필수 동의**를 둔다: 체크 상자 "개인정보처리방침에 동의합니다(필수)" + 방침 링크 + YouTube 고지 문장과 YouTube 이용약관 링크(III.A.1). 체크하기 전에는 데모·표본 버튼(뒤에는 M2b의 제출 버튼)이 동작하지 않는다.
3. 동의 상태를 앱 안에서만 들고 있는 `ConsentProvider`(메모리, 브라우저 저장소 없음)를 만들어 M3b3c가 YouTube 영상을 그릴지 정하는 데 쓴다.

## 범위 밖

- YouTube 플레이어·캡션의 YouTube 표시 → M3b3c
- 실제 입력 폼·결과 URL → M2b
- 회원 가입·동의 기록 저장(서버에 아무것도 저장하지 않는다)
- 법률 자문 — 방침 문구는 frontend-dev가 아래 점검표로 초안을 쓰고 PM이 확정한다

## 사용할 외부 출처

없음(호출 없음). 방침과 고지에 들어가는 외부 링크 2개: YouTube 이용약관 `https://www.youtube.com/t/terms`, Google 개인정보처리방침 `https://policies.google.com/privacy`. 제품 코드의 외부 주소는 `web/src/external/urls.ts` 한 파일에만 둔다(C1 예외, 아래). M3b3c가 YouTube IFrame API 주소를 같은 파일에 더한다.

## 방침 내용 점검표 (III.A.2, 리서치 3.2절)

| 항목 | 방침에 쓸 것 (사실대로 — 구현과 다르면 구현이 아니라 문구를 고치고 보고) |
|---|---|
| (a) 늘 쉽게 볼 수 있음 | 모든 화면 바닥글에 "개인정보처리방침" 링크, 동의 문장 안 링크 |
| (b) YouTube API 서비스 사용 고지 | "이 서비스는 YouTube API 서비스를 사용합니다." |
| (c) Google 개인정보처리방침 링크 | `https://policies.google.com/privacy` |
| (d) 받는 정보 | 입력한 날짜(생년월일)와 출생지(장소). 계정·이름·연락처는 받지 않는다 |
| (e) 쓰는 법·처리·공유 | 그날 자료를 찾는 데만 쓴다. 우리 서버는 날짜·사건 이름으로 위키백과·Wikidata·Wikimedia Commons·YouTube Data API에 요청한다(누구의 생년월일인지는 보내지 않는다). 날짜별 결과는 캐시하지만 요청한 사람 정보는 저장하지 않는다. 생년월일과 장소를 함께 로그에 남기지 않는다(`CLAUDE.md` 7절 6항). 장소 해석(M2a)이 생기면 그 출처를 더한다 |
| (f) 제3자 콘텐츠·광고 | YouTube 플레이어(개인정보 보호 강화 모드)를 페이지에 넣는다. YouTube가 플레이어 안에 광고를 낼 수 있다. 사진·영상은 원 출처(Wikimedia Commons 등)에서 브라우저가 직접 받는다 |
| (g) 기기 저장·쿠키 | 우리는 쿠키·브라우저 저장소를 쓰지 않는다. YouTube 플레이어와 IFrame API 스크립트는 기기에 정보를 저장하거나 읽을 수 있다 |
| III.A.1 | "영상을 재생하면 YouTube 이용약관에 동의하게 됩니다." + 약관 링크 (동의 문장 옆과 방침 안) |
| 결과 화면 주소 | 결과 화면 주소에 생년월일·장소를 넣지 않는다(리서치 위험 26) |
| 연락처·변경 | 방침 변경 날짜, 문의 방법(PM이 정함 — 비워 두면 T4에서 PM이 채움) |

## 화면

```
[입력 화면 — 임시]
  ┌──────────────────────────────────────────────┐
  │ ☐ 개인정보처리방침에 동의합니다 (필수)           │
  │   개인정보처리방침 보기(새 창에서 열림)           │
  │   이 서비스는 YouTube API 서비스를 사용합니다.   │
  │   영상을 재생하면 YouTube 이용약관(새 창에서 열림)│
  │   에 동의하게 됩니다.                            │
  └──────────────────────────────────────────────┘
  [1988년 9월 17일로 보기] …  ← 체크 전에는 aria-disabled, 누르면 체크 상자로 포커스와 안내
바닥글: 개인정보처리방침 (모든 화면)
```

- 방침은 정적 페이지 `web/public/privacy.html`(한국어, 우리 사이트 안)로 둔다. 새 창에서 열려 입력 중인 값이 사라지지 않는다.
- 동의 상태는 메모리에만 둔다. 새로 고치면 다시 동의한다(브라우저 저장소 없음 — M3b2 C4).
- 체크하지 않고 버튼을 누르면 "개인정보처리방침에 동의해야 볼 수 있습니다."를 보여 주고 체크 상자로 포커스를 옮긴다.

## 리스크와 확인할 것

1. **임시 화면에 붙는 동의** — 데모 버튼 화면에 붙였다가 M2b가 옮긴다. 구성 요소로 만들어 옮기기만 하면 되게 한다(M2b 범위에 넣음).
2. **"기능을 쓰기 전 동의"의 해석**(23번 †) — 입력 제출 전 명시적 동의로 읽는다. 법률 자문이 아니다.
3. **IFrame API 스크립트가 우리 페이지에서 돈다** — 같은 페이지의 DOM·주소를 읽을 수 있다. 결과 주소에 생년월일·장소를 넣지 않고(위험 26), 방침 (g)에 밝힌다. 화면에 보이는 입력값은 M2b 오프닝 설계 때 다시 본다.
4. **방침 문구가 구현과 어긋날 수 있다** — 서버 저장·로그 규칙이 바뀌면 방침도 고친다(M2a·M4·M6b 계획 때 확인 항목).
