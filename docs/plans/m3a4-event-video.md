# 영상 자동 검색 틀과 Commons 동영상 (M3a4)

> 브랜치: `feat/event-video` · 작성: planner · 상태: PM 승인 (2026-10-11) (2026-10-11 M3-P9 (b) 반영 개정)
> 기준: PM 미디어 결정 2026-10-11, 안전장치 1~6(PM 확인), **M3-P9 (b) 2026-10-11 — 사용자가 넣은 아무 날짜에서나 사건 영상·제공사 공식 임베드를 자동으로 찾아 보여 준다. 영상이 없는 날짜는 사진만 나오는 것이 정상**, `docs/plans/m3a3-event-media.md`(공용 미디어 형식, 안전장치), `docs/plans/m3-video-sources-research.md`, `CLAUDE.md` 7절 2·4·6항
> 선행: M3a3 `feat/event-media` 머지 + `docs/m3-video-sources` 리서치 머지(Commons 동영상 경로 "확인됨"). 리서치 결과로 planner가 "검색 경로"와 "정확도 규칙"의 세부 값을 보정한다.
> 뒤따르는 기능: M3a5 `feat/official-channel-video`(YouTube 공식 채널·대한뉴스, 키 필요), M3a6 `feat/provider-image-embed`(게티 등 공식 이미지 임베드, 조건부). 셋 다 이 기능의 **검색 틀**에 출처 어댑터 하나씩을 붙인다.

## 목표

1. 출처마다 어댑터 하나로 "사건 → 후보 미디어"를 찾는 **영상 검색 틀**을 만든다: 후보 형식, 정확도 규칙(점수와 기준선), 우선순위(안전장치 4), 개수, `tragic` 처리, 결과 캐시, 출처별 타임아웃·실패 격리.
2. 첫 어댑터로 키가 필요 없는 **Commons 동영상 자동 검색**을 붙인다(`video_file`, 원 출처 핫링크).
3. 아무 날짜에서나 동작한다: 맞는 영상이 있으면 사건 `media` 에 붙이고, 없으면 사진만 남는다(오류 아님, `partial` 도 아님).
4. 데모 날짜 큐레이션은 **확인용 기준표**로만 둔다(`data/verification/`, 응답에 쓰지 않음).

## 범위 밖

- YouTube·대한뉴스 → M3a5. 게티 등 제공사 이미지 임베드 → M3a6
- 파일 복사·서버 경유 재생 (안전장치 1)
- 웹 재생 → M3b3

## 사용할 외부 출처

| 출처 | 확신도 | 쓰는 것 |
|---|---|---|
| Wikimedia Commons (Action API) | 사진 쪽 **확인됨**. 동영상 검색 경로(QID 범주·검색 API)는 **리서치 V1 결과로 확인** | 사건 Commons 범주(P373) 또는 검색 API(`filetype:video` + 검색어)로 동영상 후보, `videoinfo`/`imageinfo` 의 원본·변환본·길이·라이선스 |
| Wikidata (M3a2 클라이언트) | **확인됨** | 사건 QID의 P373(Commons 범주) |

## 검색 틀

### 후보와 출력

```
EventMediaSearchSource (출처마다 구현)
  find(EventContext ctx) -> List<Candidate>
EventContext: date, event id, title(대표 링크), summary, wikidata_qid, scope, tone
Candidate: 공용 미디어 레코드(M3a3 형식) + 정확도 재료(제목, 설명, 명시된 날짜, 범주, 출처 종류)
```

API 응답의 미디어에 **API 전용 필드 `selection`** 을 더한다(M3a3의 `date_relation` 과 같이 저장하지 않음): `{"basis": "commons_category" | "commons_search" | "youtube_official" | "daehan_news" | "provider_embed", "score": 0~100}`. PM 품질 확인과 리뷰에 쓴다. 화면에는 보이지 않는다.

### 정확도 규칙 (자동 검색 결과가 사건과 맞는지)

후보마다 점수를 매기고 **기준선(설정값 `media.video.min-score`, 처음 60) 이상**만 붙인다. 기준선 아래면 붙이지 않는다(사진만). 원칙: **확실하지 않으면 붙이지 않는다**.

| 재료 | 점수 | 근거 |
|---|---|---|
| 사건 연결: 사건 QID의 Commons 범주 안에 있음 | +50 | 사람이 사건에 분류한 파일 |
| 날짜 일치: 제목·설명·촬영일 필드에 사건 날짜(같은 날)가 명시 | +40 / 같은 달 +20 / 같은 해 +10 | 6.1절 정밀도 |
| 사건어 일치: 대표 링크 제목의 핵심어(조사·연도·일반어 제외 후) 절반 이상이 제목·설명에 | +30 | 이름만 같은 다른 사건을 줄임 |
| 공식 출처: 허용 채널·기관(M3a5) | +20 | 안전장치 4 |
| 자유 라이선스 (`license_status: free`) | +10 | 안전장치 4 |
| 사건 연도와 다른 연도가 제목에 명시 | −40 | 기념 행사·재방송·회고 영상 |
| "재현", "기념", "주년", "다시 보는", "anniversary", "reenactment" 같은 말 | −30 | 그날 영상이 아님 |

- 필수 조건(점수와 별개): 날짜 일치가 최소 "같은 해"이거나 사건 범주 안에 있어야 한다. 둘 다 아니면 버린다.
- `captured_at`·`date_precision` 은 **명시된 촬영·방송 날짜**로만 채운다. 업로드·게시일은 쓰지 않는다(6.1절). 명시가 없으면 `null`("촬영 시점 미상"). 주간 발행 뉴스는 `approx`.
- 리서치 V7 결과로 점수 값과 낱말 목록을 보정한다.

### 우선순위·개수·`tragic`

| 규칙 | 내용 |
|---|---|
| 순서 | 안전장치 4: 자유 라이선스 → 공식 채널·제공사 공식 임베드 → 그 밖. 같은 단계는 점수 순 |
| 개수 | 사건마다 영상 최대 1, 제공사 이미지 임베드 최대 1(M3a6). 영상 검색은 날짜 앞쪽 사건부터 **최대 3개 사건**까지(쿼터·지연 제한, 설정값 `media.video.max-events`) |
| `tragic` | `tragic` 사건은 영상을 찾지 않는다(잔혹한 장면 위험, 6.3절). `tragic` 사건이 있는 날은 날짜 단위 영상도 붙이지 않는다 |
| 차단·제외 | M3a3 차단 목록, 통신사·언론사 제외 규칙(직접 재생 금지)을 같은 정규화로 |
| 영상 없음 | 정상. 사건 `media` 에 사진만 남고 `partial` 은 바뀌지 않는다 |
| 실패 | 출처 하나가 실패·시간 초과면 그 출처만 건너뛰고 `partial: true`. 영상 검색 전체 시간 상한(설정값, 처음 3초)을 넘으면 그때까지 찾은 것만 쓴다 |

### 결과 캐시

- 검색 결과(후보 식별자·점수, 미디어 파일 아님)를 날짜·사건 단위로 캐시한다(Flyway V3 `event_media_search_cache`, TTL 설정값 7일). 출처별 캐시 허용 기간이 리서치 결과로 더 짧으면 그 값을 쓴다(YouTube는 M3a5에서 약관대로).
- 저장하는 것은 날짜·사건 ID·출처·식별자·점수·조회 시각뿐이다(요청한 사람 정보 없음).

### 확인용 기준표 (`data/verification/event-media-expectations.json`, content-curator)

데모 날짜 3개와 표본 날짜 5개(1950-06-25, 1969-07-20, 1986-09-20, 2000-02-29, 2014-04-16 — 리서치 계획서와 같음)마다 "사람이 찾아본 결과 있어야 할 것/없어야 할 것"을 적는다: 예 "1988-09-17 올림픽 사건에는 개막식 영상이 Commons에 있으면 붙어야 함", "2014-04-16은 `tragic` 이라 영상 없음", "1995-03-15는 사건 없음". 응답에 쓰지 않고 PM 품질 확인(T5)과 test-engineer 표에서 대조한다.

## 테스트 방침

- M3a1 "테스트 방침"을 따른다. Commons 동영상 응답은 녹화 fixture(데모 날짜)와 합성 fixture(표본 날짜·경계 사례).
- 자동 검색 결과는 날짜마다 다르므로 **자동 테스트는 fixture로 규칙만** 확인하고, **실제 품질은 PM 품질 확인(T5)** 으로 본다.
- 표본 날짜는 공개된 역사 사건 날짜와 경계값이라 실제 사람의 생년월일이 아니다(`CLAUDE.md` 7절 6항).

## 리스크와 확인할 것

1. **엉뚱한 영상이 붙을 수 있다** — 이름만 같은 다른 사건, 기념 영상, 재현 영상. 대응: 정확도 규칙(사건 범주·날짜 명시·사건어·다른 연도 감점·기념어 감점), 기준선, PM 품질 확인, 차단 목록. 확실하지 않으면 붙이지 않는다(사진만).
2. **검색 정확도가 날짜마다 다르다** — 표본으로 확인하지만 모든 날짜를 보장하지 않는다. 기준선을 보수적으로 둔다.
3. **`tragic` 날짜** — 영상은 찾지 않는다. `tone` 오판(비극을 `normal` 로)이면 비극 영상이 붙을 수 있다 → M3a2의 보수적 기본값(판정 불가면 `tragic`)이 막는다.
4. **지연** — 사건마다 외부 검색이 늘어난다. 시간 상한, 사건 3개 제한, 결과 캐시로 10초 목표를 지킨다. M6b에서 측정.
5. **저작권** — 로드맵 리스크 4.
