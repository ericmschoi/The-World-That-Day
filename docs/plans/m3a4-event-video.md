## 목표

1. 출처마다 어댑터 하나로 "사건 → 후보 미디어"를 찾는 **영상 검색 틀**을 만든다: 후보 형식, 정확도 점수와 필수 조건, 기준선, 우선순위(안전장치 4), 개수, 길이 상한, `tragic` 처리, 출처별 타임아웃·실패 격리, 전체 시간 상한, `selection` 필드.
2. 정확도 규칙을 리서치 7절 종합안대로 만든다(R-T1~R-T4, R-V1~R-V7, R-Y1·R-Y2·R-Y4, R-N3).
3. 이 기능에는 실제 외부 출처가 없다. 가짜 어댑터로 규칙을 시험하고, 리서치 7절 "점수 확인" 표의 후보를 합성 후보로 만들어 점수가 같게 나오는지 본다.
4. 아무 날짜에서나 동작한다. 맞는 영상이 없으면 사진만 남는다(오류 아님, `partial` 도 아님).

## 검색 틀

### 후보와 출력

```
EventMediaSearchSource (출처마다 구현)
  find(EventContext ctx) -> List<Candidate>
EventContext: date, event id, title(대표 링크 제목, 한국어), english_label(사건 QID 영어 라벨, 없으면 null — M3a4b가 채움),
              summary, wikidata_qid, scope, tone
Candidate: 공용 미디어 레코드(M3a3 형식) + 정확도 재료
정확도 재료: text(제목·설명), original_capture_date(Commons DateTimeOriginal, YouTube recordingDate — 원본 값),
            explicit_dates(출처가 준 명시 날짜. 예: 대한뉴스 회차 날짜), event_link(p10 | category_direct | none),
            official(허용 채널 ID 대조 결과), retrospective(회고 편집물 표시 — M3a5가 정함),
            date_text_excluded(제목·설명 날짜를 날짜 재료로 쓰지 않음 — M3a5가 대한뉴스 제목에 표시), duration_seconds, basis
```

API 응답의 미디어에 **API 전용 필드 `selection`** 을 더한다(M3a3의 `date_relation` 처럼 저장하지 않음): `{"basis": "commons_p10" | "commons_category" | "commons_date_category" | "commons_search" | "youtube_official" | "daehan_news", "score": 정수}`. 점수는 합계 그대로다(100을 넘을 수 있다). PM 품질 확인과 리뷰에 쓰고 화면에는 보이지 않는다.

### 정확도 규칙 (리서치 7절 종합안)

후보마다 점수를 매기고 **필수 조건을 모두 채우고 기준선(설정값 `media.video.min-score`, 처음 60) 이상**인 것만 붙인다(M3-P11). 원칙: **확실하지 않으면 붙이지 않는다**.

| 재료 | 점수 | 계산 | 근거 |
|---|---|---|---|
| 사건 연결 | +50 | `event_link` 가 `p10`(사건 QID의 `P10` 에 든 파일) 또는 `category_direct`(사건 범주 직속 파일 — 범주는 `P373`, 없으면 `P910` 항목의 commonswiki 사이트링크). 하위 범주는 점수 없음 | R-V1, R-V2, 10.1절 1번 (a) |
| 날짜 일치 | 같은 날 +40 / 같은 달 +20 / 같은 해 +10 | 재료 중 사건 날짜에 가장 가까운 하나: (1) 제목·설명에 적힌 날짜(M3a3 파서. 한국어·ISO에 더해 영어 "July 20, 1969", "20 July 1969", "17th September 1988". `date_text_excluded` 면 쓰지 않음), (2) `original_capture_date` — **사건 날짜보다 늦으면 재료에서 뺀다**, (3) `explicit_dates`(대한뉴스 회차 날짜). 업로드·게시일(Commons `DateTime`, YouTube `publishedAt`)과 `insource:` 일치는 날짜 재료가 아니다 | R-V3, R-V4, R-Y1, R-N3 |
| 사건어 일치 | +30 | 아래 "사건어 대조" 중 하나라도 맞으면(둘 다 맞아도 +30) | R-T2, R-T3 |
| 공식 출처 | +20 | `official` (허용 채널을 **채널 ID**로 대조한 결과, M3a5) | R-Y4, 안전장치 4 |
| 자유 라이선스 | +10 | `license_status: free` | 안전장치 4 |
| 다른 연도 | −40 | 제목에 사건 연도와 다른 4자리 연도(1900~2099)가 있음. 자료 번호 안 연도도 걸린다(의도) | R-V6 |
| 기념어 | −30 | 제목·설명에 설정 목록 `media.video.commemoration-words` 의 낱말: 재현, 기념, 기념식, 주년, 다시 보는, 추모, anniversary, reenactment, montage, highlights, comparison, memorial, commemoration, tribute. "restored"는 넣지 않는다 | R-V5 |
| 다른 단계 | −40 | 제목·설명에 설정 목록 `media.video.other-stage-words` 의 낱말: 발사, launch, 리허설, rehearsal, 예행연습, 카운트다운, countdown, 훈련, training, 준비, preparation. 한국어 낱말은 띄어쓰기를 없애고 대조한다("카운트 다운"도 걸림). **그 낱말이 사건 제목·요약에 있으면 감점하지 않는다**(발사가 사건인 날) | R-T1(6bf0267), 3.5절 Y2 |

사건어 대조:
- 핵심어: 대표 링크 제목에서 연도("1988년", "1988"), 조사, 일반어 목록(설정값 `media.video.stopwords`)을 뺀 낱말. 영어 라벨도 같은 방식(소문자, 관사·전치사 제외).
- 한국어: 후보 글과 핵심어의 띄어쓰기를 모두 없애고, 핵심어마다 후보 글에 부분 문자열로 있는지 본다. **절반 이상**이 있으면 일치. 예: "1986년 아시안 게임" → {아시안, 게임} ↔ "1986년 서울아시안게임 개막식"(둘 다 있음).
- 영어: 영어 라벨 핵심어의 절반 이상이 후보 글에 낱말로 있으면 일치(대소문자 무시). 예: "Apollo 11" ↔ "Historic Apollo 11 Moonwalk Footage".
- **숫자가 든 핵심어는 반드시 있어야 한다**(절반을 넘겨도 숫자 핵심어가 없으면 불일치). 예: "서울 지하철 7호선" ↔ "서울 지하철 2호선 개통" → 불일치. "아폴로 11호" ↔ "아폴로 8호" → 불일치.
- `english_label` 이 `null` 이면 한국어만 본다.

필수 조건 (점수와 별개):
1. **날짜 일치(같은 해 이상) 또는 사건어 일치 중 하나는 있어야 한다.** 사건 연결(+50)과 자유 라이선스(+10)만으로는 붙지 않는다(R-T4).
2. `commons_date_category`(날짜 범주에서 온 후보)는 사건어 일치가 있어야 한다. `commons_search`(보조 검색어에서 온 후보, M3a4b T4)는 같은 날 날짜 일치와 사건어 일치가 **둘 다** 있어야 한다.
3. **길이**: `duration_seconds` 가 상한(설정값 `media.video.max-duration-seconds`, 600 = 10분, 10.1절 3번 (a))보다 길거나 `null` 이면 버린다.
4. 점수가 기준선 이상.

### 촬영 시점 규칙

`captured_at`·`date_precision` 은 **명시된 촬영·방송 날짜**로만 채운다(6.1절). 어디서 읽는지는 출처마다 다르다.

| 출처 | `captured_at` 을 읽는 곳 | 비우는 경우 |
|---|---|---|
| Commons (M3a4b) | `DateTimeOriginal` (M3a3 파서) | 사건 날짜보다 늦음(업로드·복원일로 봄, R-V3). 설명문 날짜는 점수 재료로만 쓰고 촬영 시점으로 옮기지 않는다(10.1절 2번이 (c)를 고르지 않음) |
| YouTube (M3a5) | 제목·설명에 적힌 날짜, 사건 날짜 이하인 `recordingDate`(표본 5개는 모두 비어 있음, 3.5절) | 회고 편집물(`retrospective`) — 날짜 점수는 주되 비운다(R-Y3). 대한뉴스 제목(`date_text_excluded`) — 설명의 "제작일"은 회차 날짜라 촬영 시점이 아니다(M3a5b가 다룸). `publishedAt` 은 쓰지 않는다 |
| 대한뉴스 (M3a5b) | 색인의 회차 날짜, `approx`(R8로 `captured_at` 은 연도) | 길이 대조 실패(R-N6), 설명 "제작일"과 색인 날짜가 다름(R-N8) |

- 비우면 `date_relation.kind = unknown`, 화면 "촬영 시점 미상", "같은 날" 배지 없음.
- 사건 범주 직속·`P10` 이고 사건어가 맞아 붙은 영상은 촬영 시점이 늦거나 없으면 **"촬영 시점 미상"으로 붙는다**(10.1절 2번 (b)).
- 사건 날짜·범주·점수의 "날짜 일치" 판단을 `captured_at` 으로 옮기지 않는다.

### 우선순위·개수·`tragic`

| 규칙 | 내용 |
|---|---|
| 순서 | 안전장치 4: 자유 라이선스 → 공식 채널 → 그 밖. 같은 단계는 점수 순 |
| 개수 | 사건마다 영상 최대 1. 영상 검색은 날짜 앞쪽 `normal` 사건부터 **최대 3개**(설정값 `media.video.max-events`, M3-P12) |
| 같은 영상 | 두 경로에서 같은 `id` 가 나오면 하나만, 점수가 높은 쪽(같으면 `daehan_news` > `youtube_official`, `commons_p10` > `commons_category` > `commons_date_category` > `commons_search`) |
| `tragic` | `tragic` 사건은 어댑터를 부르지 않는다. `tragic` 사건이 있는 날은 날짜 단위 경로(날짜 범주 등)도 부르지 않는다 |
| 차단·제외 | M3a3 차단 목록, 통신사·언론사 제외 규칙(`image`·`video_file` 에만), R9 주소 형식. 자유 라이선스로 올라온 언론사 영상(예: 뉴스타파)은 허용하고 차단 목록으로 대응(10.1절 4번 (a)) |
| 영상 없음 | 정상. 사건 `media` 에 사진만 남고 `partial` 은 바뀌지 않는다 |
| 실패 | 출처 하나가 실패·시간 초과면 그 출처만 건너뛰고 `partial: true`. 쿼터를 다 써서 건너뛴 것(M3a5)은 실패가 아니라 `partial` 을 바꾸지 않는다. 영상 검색 전체 시간 상한(설정값, 처음 3초)을 넘으면 그때까지 찾은 것만 쓴다 |

## 리스크와 확인할 것

1. **엉뚱한 영상** — 이름만 같은 다른 사건, 기념·재현·발사일·예행연습·카운트다운 영상, 노선·회차 번호만 다른 같은 종류의 사건. 대응: 직속 범주·`P10` 만, 사건어(한국어·영어·숫자 핵심어), 필수 조건, 감점, 기준선, PM 품질 확인, 차단 목록.
2. **경계값 60** — 점수 확인 표 8행(KTV 1986 개막식)이 딱 60이다. 리서치는 기준선을 올리기보다 품질 확인 뒤 낱말 목록을 보정하자고 했다(10.1절 21번). 그래서 기준선은 60 그대로 두고 M3a5 T4에서 본다.
3. **핵심어가 하나뿐인 짧은 제목** — "절반 이상" 규칙이 1/1로 쉽게 맞는다. 필수 조건과 기준선이 같이 걸러 낸다. 품질 확인에서 엉뚱한 결과가 보이면 일반어 목록을 늘린다.
4. **영어 라벨이 없는 사건** — 한국어만 대조하므로 영어 메타데이터 파일은 사건어 점수를 못 받는다. 사진만 나오는 쪽으로 틀린다(안전한 쪽).
5. **표본이 작다** — 9개 후보로 맞춘 값이다. M3a4b·M3a5·M3a5b의 PM 품질 확인으로 보정한다(M3-P11).
6. **`tragic` 오판** — 비극을 `normal` 로 잘못 보면 비극 영상이 붙을 수 있다. M3a2의 보수적 기본값(판정 불가면 `tragic`)이 막는다.
7. **대표 링크가 사건이 아닌 줄**(R-V8) — 다른 항목의 범주·라벨로 검색하게 된다. 필수 조건(사건어)이 일부 막는다. 후속 작업 후보로 두었다.
