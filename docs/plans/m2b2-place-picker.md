# M2b2 장소 해석 연결과 후보 선택 화면 (M2)

> 브랜치: `feat/place-picker` (M2b 머지 뒤 `main` 에서) · 작성: planner (2026-10-27) · 상태: **PM 승인 (2026-10-27, M2 공통 결정 추천대로)**
> 기준: API 계약 `docs/plans/m2a-place-resolve.md` "`GET /api/places/resolve`"(이 PR은 계약만 믿고 만든다 — M2a 머지 전에도 MSW로 가능), M2b의 입력 폼·오프닝·C-규칙(`docs/plans/m2b-input-and-opening.md`), 제품 정의서 4절(후보가 여럿이면 고르게, 찾지 못하면 동 단위로 다시, 국외 안내), M3b2b T0의 응답 모양 검사(`world/worldShape.ts`)
> 서버 작업이 없다(★ 없음).

## 목표

1. 제출하면 장소를 `GET /api/places/resolve` 로 보내고, 결과에 따라: 후보 1개 → 바로 결과 화면, 여러 개 → 후보 선택 화면, `NOT_FOUND`·`OUTSIDE_KOREA`·실패 → 장소 칸 아래 안내.
2. 오프닝의 장소를 고른 후보의 `name` 으로(입력 글자 대신).
3. 장소 유형이 `REGION` 이면 "그날의 동네" 섹션을 그리지 않는다(제품 정의서 5절 2번 — 동네·장소에만).
4. 날짜와 장소가 한 요청에 함께 가지 않는다. 고른 후보는 메모리에만.
5. 개인정보처리방침: 장소를 우리 서버로 보낸다는 것과 지역 목록.

## 범위 밖

- 서버(M2a·M2a2). 카카오 출처 문장은 M2a2 T5.
- 고른 후보를 다른 섹션 요청에 보내기(M4·M5가 정함).
- 후보 2쪽 이상 보기, 지도에서 고르기(M2-P2).

## 사용할 외부 출처

없음 (우리 백엔드만). 시험은 MSW·Playwright 가로채기에 **우리 API 계약 모양의 합성 응답**만 쓴다(카카오 응답이 아님).

## API / 데이터 변경

API는 M2a 계약 그대로. 웹 파일: `web/src/places/types.ts`(계약 타입), `api.ts`(`resolvePlace(q, signal)`, 기본 10초), `placeShape.ts`(모양 검사 — 맞지 않으면 실패로 다룸, 모르는 `type` 의 후보는 뺌), `PlaceCandidates.tsx`, MSW 기본 핸들러와 fixture `web/src/mocks/fixtures/places/`.

### 흐름

| 서버 답 | 화면 |
|---|---|
| 200 `FOUND`, 후보 1개 | 결과 화면(오프닝 = 후보 `name`) |
| 200 `FOUND`, 후보 2개 이상 | 후보 선택 화면 |
| 200 `NOT_FOUND` | 장소 칸 아래: "장소를 찾지 못했습니다. 문을 닫았거나 이름이 바뀐 곳이면 동 이름으로 다시 입력해 주세요(예: 망원동). 대한민국 밖의 장소는 아직 지원하지 않습니다." |
| 200 `OUTSIDE_KOREA` | 장소 칸 아래: "대한민국 밖의 장소는 아직 지원하지 않습니다." |
| 400 `PLACE_QUERY_*` | M2b의 장소 문구와 같은 문구 |
| 503, 시간 초과(10초), 모양이 틀린 답, 그 밖의 오류 | 장소 칸 아래: "지금은 장소를 찾을 수 없습니다. 잠시 뒤 다시 해 주세요." |

- 찾는 동안 제출 버튼 `aria-busy="true"` 와 글자 "찾는 중…", 두 번 제출해도 요청은 하나. 입력 화면을 떠나면 요청을 끊는다(`AbortSignal`).
- 장소 칸 아래 안내는 `aria-describedby` 로 연결하고 포커스를 장소 칸으로.

### 후보 선택 화면

| 요소 | 규칙 |
|---|---|
| 제목 | `h2` "어느 곳인가요?", `tabIndex={-1}`, 화면이 열리면 포커스 |
| 목록 | 후보마다 버튼 하나(서버 순서 그대로, 미리 고른 것 없음). 버튼 안: `name`(굵게), `full_name` 또는 `address`, 유형 글자(`REGION` "시·도·시·군·구", `NEIGHBORHOOD` "동네", `SPOT` "장소"), `category`(있으면) |
| 더 있음 | `more: true` 면 "후보가 더 있습니다. 시·도나 시·군·구 이름을 함께 넣으면 좁힐 수 있습니다." |
| 출처 | `sources` 이름을 "장소 정보: …"로(링크는 새 창, 기존 `NewTabLink`) |
| 다시 입력 | 버튼 "다시 입력" → 입력 화면, 포커스는 장소 칸, 값은 그대로 |

### 날짜·장소 분리 (C-규칙 더하기)

| # | 규칙 |
|---|---|
| C6 | `/api/places/resolve` 요청에는 `q` 만, `/api/story/world` 요청에는 `date` 만. 어떤 요청 주소에도 날짜와 장소가 함께 없다. 출생 시각은 어디에도 없다 |
| C7 | 고른 후보(`id`·좌표 포함)는 React 상태에만. 주소·저장소에 없음(M2b C1·C2 그대로) |

## 리스크와 확인할 것

1. **M2a 머지 전에 만든다** — 계약을 믿고 만든다. M2a 리뷰에서 계약이 바뀌면 이 PR의 T1이 따라간다(계약 변경은 M2a 계획서를 먼저 고친다).
2. **M2a2 전에는 동네·장소가 503** — "지금은 찾을 수 없습니다" 문구가 사실과 맞다. M2a2 머지 뒤 웹 변경 없이 채워진다.
3. **후보 1개면 확인 없이 진행** — 제품 정의서 4절은 "여러 개면 고르게"다. 1개인데 사용자가 원한 곳이 아닐 수 있다 → 결과 화면의 "처음으로"로 돌아가 고칠 수 있다. 결과 검수(M2 끝)에서 다시 본다.
4. **안내 문구 예시** — "망원동"은 제품 정의서 3·4절의 예라 화면 문구에만 쓰고 시험 질의로는 쓰지 않는다.
