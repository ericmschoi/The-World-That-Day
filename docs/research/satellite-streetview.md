# 현재 위성·로드뷰 — 출처 검증

> 작업: T3 · 계획서: docs/plans/m0-source-research.md · 조사 일자: 2026-10-09 · 작성: data-researcher
> 이 문서의 약관 해석은 법률 자문이 아니다. 확신도 기준은 계획서의 "확신도 기준"을 따른다.
> 이 영역의 후보는 모두 키가 필요하다. 그래서 실제 응답은 하나도 보지 못했고, 공식 문서로만 판단했다. 공식 문서 중 일부는 이 도구로 읽지 못했다. 카카오 지도 Web API 레퍼런스는 본문이 자바스크립트로 그려져 목차만 읽혔다 [2]. Google Maps Platform 서비스 약관과 서비스별 약관은 본문이 비어 있었다 [29][30]. 브이월드 개발자 사이트는 연결이 끊겼다 [34]. 네이버 Maps 약관 PDF는 이번에는 텍스트로 읽히지 않아 T1에서 읽은 조항을 인용했다 [16].

## 1. 요약

- 1순위는 **카카오맵 지도 Web API(스카이뷰 + 로드뷰, JS SDK로 실시간 표시)** 다. 종합 확신도는 `미확인` 이다. 로드뷰·스카이뷰 커버리지를 적은 공식 문서가 없기 때문이고, 나머지 필수 항목은 `부분 확인` 이다. 장소 검색 1순위(T1, 카카오 로컬)와 콘솔·쿼터를 함께 쓴다. 무료 한도가 하루 300,000건으로 가장 크다 [6]. 공식 문서에서 다른 이미지와 함께 표시하는 것을 막는 조항은 찾지 못했다 [7][8].
- 가장 중요한 제약은 두 가지다. 첫째, **어느 제공자도 API로 과거 시점 로드뷰를 고를 수 없다** [2][11][20]. 그래서 로드뷰는 "현재 모습" 용도로만 쓸 수 있다. 둘째, **세 회사 모두 이미지를 저장·캐시해 다시 내보내기 어렵다** [7][18][25]. 그래서 화면은 SDK나 API로 그때그때 그려야 한다. 표시용 키는 브라우저에 둘 수밖에 없다(제품 정의서 8절 예외) [1][13][26].
- 촬영일은 제공자마다 다르다. Google Street View는 서버에서 무료로 부르는 메타데이터가 `YYYY-MM`(또는 연도만)을 준다 [17]. 네이버 거리뷰는 `photodate` 를 주지만 형식은 문서에 없다 [11]. 카카오 로드뷰와 모든 제공자의 위성 이미지는 촬영일을 주지 않는다 [2][12][24].
- 그때/지금 비교의 "지금" 쪽은 **카카오 스카이뷰를 나란히 놓는 조합**을 추천한다. 라이선스가 가장 단순한 것은 **브이월드 WMTS(공공누리 제1유형)** 조합이지만, 브이월드 약관을 아직 읽지 못했다. Google 위성은 추천하지 않는다. Google 문서에 "Google 지도에만 표시" 조건이 있고 [25], 비Google 지도와 함께 쓰지 못하게 하는 약관 조항이 있다는 단서가 있기 때문이다 [S3].
- 제품 정의서와 다른 점: 6.1·6.2절의 `현재 모습`·`current` 는 최신 이미지라는 뜻이지만, 실제로는 촬영 시점을 모르거나 몇 년 전 사진일 수 있다. 또 SDK로 그리는 미디어는 `url`·`thumbnail_url` 을 채울 수 없다(9절).

## 2. 확인할 질문과 답

질문 번호는 계획서 "T3 작업별 기준"의 번호다. 제품 정의서 7절의 "M0에서 확인할 것" 3개 항목(웹 임베드 방법, 과거 시점 제공 여부, 캐싱 금지 등 약관)은 질문 열에 `(7절)` 로 표시했다. 출처 약칭은 다음과 같다.

- **카카오**: 카카오맵 지도 Web API(JS SDK의 로드뷰·스카이뷰·StaticMap)와 정적 지도 REST API

## 3. 출처 카드

### 출처 — 카카오맵 지도 Web API (스카이뷰·로드뷰·StaticMap) / 정적 지도 REST API
- 구분: 제품 정의서 후보
- 제공 기관 / 공식 문서: 카카오 / Kakao 지도 Web API 가이드 [1], 레퍼런스 [2](본문이 자바스크립트로 그려져 목차만 읽힘), 소개 [3], 카카오맵 이해하기 [4], 카카오맵 REST API(정적 지도) [5], 쿼터 [6], 운영 정책 [7], 플랫폼 서비스 약관 [8]
- 무엇을 얻나:
  - JS SDK: 지도(`Map`, `MapTypeId`), 로드뷰 뷰어(`Roadview`), 좌표 근처 파노라마 찾기(`RoadviewClient.getNearestPanoId`), 지도 위 로드뷰 경로 표시(`RoadviewOverlay`), 이미지 지도(`StaticMap`, `setMapTypeId` 있음) [2]. 스카이뷰(위성)는 `MapTypeId` 로 고르는 것으로 보인다. 상수 이름(`SKYVIEW`, `HYBRID`)은 공식 본문에서 읽지 못했고 포럼 글에서만 봤다(단서 [S1]).
  - 정적 지도 REST: 중심 좌표와 레벨로 만든 PNG·JPG 이미지, 마커 최대 5개, 최대 2048x1024, 카카오 로고 포함 [5]. 문서에 지도 종류 파라미터가 없어 위성 정적 이미지는 받을 수 없는 것으로 보인다.
- 접근 방법: 웹 임베드(SDK) + REST API(정적 지도)
- 인증·키: JS SDK는 JavaScript 키(브라우저 키)를 쓰고 JavaScript SDK 도메인을 등록해야 한다. `http://localhost:8080` 등록 예가 있다 [1][4]. 정적 지도 REST는 `Authorization: KakaoAK ${REST_API_KEY}`(서버 키)다 [5]. 지도 SDK에 REST 키를 쓰면 안 된다 [4]. 2026-07-21부터 앱 관리 페이지에서 카카오맵 "사용 설정"을 켜야 한다 [4]. 승인 심사는 문서에 없다.
- 요금·쿼터: 지도 Web SDK 하루 300,000건 무료, 초과 건당 0.1원. 정적 지도 REST 하루 1,000건 무료, 건당 2원. 월 전체 3,000,000건. 쿼터와 요금은 "추후 변경될 수 있습니다" [6]. 무료 쿼터는 처음 활성화한 앱에만 있다 [4]. 로드뷰 계수 방식은 미확인이다.
- 커버리지: 연도 범위는 해당 없음(현재 이미지). 로드뷰·스카이뷰의 지역 커버리지는 문서에 없다. 한국어 서비스다.
- 날짜 정밀도: 불명 — 촬영일을 돌려주는 메서드가 레퍼런스 목차에 없다 [2]
- 응답 메타데이터: 촬영일 없음 [2]. 좌표는 SDK의 `LatLng`(위도·경도)이고, 정적 REST는 `coord` 기본값이 `WGS84` 다 [2][5]. 라이선스 필드 없음.
- 라이선스·약관 핵심:
  - 화면 표시: SDK로 그려 보여주는 것이 제공 목적이다 [1][3].
  - 캐싱·저장: 운영정책 제5조 20호(사용자 환경 개선 목적·최신 유지 조건의 캐시만), 30호(사전 승낙 없는 복사·복제 금지) [7]. 플랫폼 서비스 약관 제11조 ③항(정보의 사전 승낙 없는 복사·복제 금지)과 ② 9호(서비스의 복사·수정·배포 금지) [8]. 이미지·스크린샷 저장을 따로 다룬 조항은 없다(D5).
  - 상업 이용: 제5조 11호는 허가되지 않은 상업적 판매·재판매를 금지한다 [7]. 유료 요금제는 있다 [6]. 명시적 허용 문장은 없다.
  - 출처 표시: 정적 REST는 로고 "제거 불가" [5]. SDK는 저작권 표시 위치를 정하는 `setCopyrightPosition` 이 있다 [2]. 디자인 가이드 준수는 "권장"이다 [4]. 상표는 제18조를 따른다 [7].
  - 변경(크롭·리사이즈·겹치기): 제11조 ② 9호가 서비스의 "수정"을 금지한다 [8]. 반면 Web API 소개는 지도 위에 HTML 콘텐츠를 올리는 것을 기능으로 안내한다 [3]. 나란히 놓기나 겹치기를 막는 조항은 찾지 못했다.
- 이 서비스에 맞는가: **조건부**.
  - 비상업일 때: 스카이뷰("지금" 위성)와 로드뷰를 SDK로 실시간 표시하는 용도로 맞다. 단, (1) 촬영일이 없으므로 "촬영 시점 미제공"으로 표기해야 하고(D2), (2) 이미지를 저장하지 않으며, (3) JavaScript 키를 도메인 제한과 함께 브라우저에 둔다.
  - 상업일 때: 위 조건은 같다. 무료 쿼터를 넘으면 비즈월렛 연결과 유료 설정이 필요하다 [4]. 상업 이용 허용은 공식 문서로 확인하지 못했다.

### 출처 — 브이월드 WMTS 영상 (현재 영상 용도)
- 구분: 추가 후보
- 제공 기관 / 공식 문서: 국토교통부 국가공간정보센터 / 공공데이터포털 WMTS/TMS API [31], 배경지도 API [32]. 브이월드 WMTS 가이드 [34]는 연결이 끊겼다(socket hang up). 접근 방법·인증·라이선스 기본 내용은 T2 카드(`docs/research/aerial-imagery.md` 3절 "출처 — 브이월드")를 참조하고, 여기서는 현재 영상 용도의 질문만 새로 답한다.
- 무엇을 얻나: 영상(위성)·하이브리드 등 WMTS 배경지도 타일 [31]. 영상이 위성 사진인지 항공 정사영상인지, 몇 년도 영상인지는 문서에 없다.
- 접근 방법: 타일·WMTS (EPSG:3857 [31]). 요청 주소 형식은 첨부파일과 브이월드 가이드에만 있어 읽지 못했다.
- 인증·키: 브이월드 인증키(T2). 서버 키인지 브라우저 키인지, 서비스 URL 등록 방식은 미확인. 배경지도 API는 개발 자동승인, 운영 "심의승인"이다 [32].

- 커버리지: "대한민국 전체"(배경지도 API) [32]. 시간범위 "매년 구축 후 갱신" [31].
- 날짜 정밀도: 불명 — 시간범위와 업데이트 주기 표기가 서로 맞지 않고 [31], 촬영일 필드는 문서에 없다

- 라이선스·약관 핵심: 공공데이터포털 표기는 WMTS/TMS API가 공공누리 제1유형 [31], 배경지도 API가 "제한 없음" [32]이다. 제1유형은 출처 표시 조건으로 상업 이용·변경을 허용한다(T2 [20]). 브이월드 이용약관(캐싱, 로고, 다른 지도와 함께 표시)은 읽지 못했다(T2 B7).
- 이 서비스에 맞는가: **조건부**.
  - 비상업일 때: 그때 쪽(국토지리정보원 항공사진)과 같은 국가 기관 계열이라, 제1유형이 확인되면 나란히 놓기·겹치기가 라이선스상 가장 단순하다. 그러나 엔드포인트, 키 종류, 약관, 영상 연도를 모두 확인하지 못했다.
  - 상업일 때: 제1유형이면 상업 이용 가능. 약관 확인 후 판단.

결론:
- **카카오(로드뷰·스카이뷰)**
  - 비상업일 때: `embed` 가 되는 조건은 네 가지다. (1) SDK로 실시간 표시하고, (2) 이미지·스크린샷을 저장하지 않고, (3) 로고·저작권 표시를 가리지 않고, (4) 촬영 시점 미제공을 표기한다(D2). 이 조건을 지킬 수 없는 화면(예: 공유용 이미지 생성)이면 `link_only` 다.
  - 상업일 때: 조건은 같다. 상업 이용 허용이 명시되지 않아(제5조 11호) 상업화 결정 때 카카오에 확인해야 한다.
- **네이버(거리뷰·위성)**
  - 비상업일 때: 요청 안에서 즉시 1회 표시하면 `embed` [16]. 결과를 저장하거나 다음 요청에 재사용하면 안 된다.
  - 상업일 때: 같다(재판매만 금지 [16]).
- **Google(Street View·위성)**
  - 비상업일 때: 단독 화면이면 `embed`. 국가 항공사진이나 다른 회사 지도와 같은 화면이면 D4가 풀리기 전까지 쓰지 않는다(`link_only` 도 아니고 미표시).
  - 상업일 때: 같다. 약관 본문 확인이 필요하다.
- **국가 WMTS**
  - 비상업·상업 모두: 제1유형이 플랫폼 약관과 충돌하지 않으면 출처를 표시하고 `embed`. 약관 확인 전까지는 잠정이다.

## 6. PM이 실행할 확인 명령

공통 규칙:
- 키는 환경변수로만 넣는다. 제안 이름: `KAKAO_REST_API_KEY`(서버), `NCP_MAPS_CLIENT_ID`·`NCP_MAPS_CLIENT_SECRET`(서버), `GOOGLE_MAPS_SERVER_KEY`(서버). 브라우저 SDK용 이름(`VITE_KAKAO_JS_KEY`, `VITE_NCP_MAPS_CLIENT_ID`, `VITE_GOOGLE_MAPS_BROWSER_KEY`)은 명령에 쓰지 않으며, 도메인 제한 방법은 7절 비교표에 적었다.
- 이미지를 받는 명령은 `-o /dev/null` 로 버리고 HTTP 상태와 Content-Type만 출력한다. 이미지 파일을 저장하지 않는다.
- 응답 원문은 저장소에 커밋하지 않는다. "응답에서 확인할 것"의 값만 data-researcher에게 넘겨 준다.
- 장소는 데모 장소만 쓴다. `<X>`·`<Y>`(경도·위도)에는 T1 `place-search.md` 6절 K2(광주 서구 풍암동)나 K3(서울대학교병원)의 결과 값을 넣는다.

### 카카오 (K-S1)

```bash
# K-S1 — 근거: https://developers.kakao.com/docs/ko/kakaomap/rest-api (정적 지도: center, size, lv, Authorization: KakaoAK)
# <X>,<Y> 에는 T1 K3(서울대학교병원) 첫 후보의 x, y 를 넣는다.
curl -sS -G "https://dapi.kakao.com/v2/maps/staticmap" \
  -H "Authorization: KakaoAK $KAKAO_REST_API_KEY" \
  --data-urlencode "center=<X>,<Y>" \
  --data-urlencode "size=400x300" \
  --data-urlencode "lv=3" \
  -o /dev/null -w "%{http_code} %{content_type}\n"
# 응답에서 확인할 것: 200 과 image/png. 401·403이면 카카오맵 사용 설정 여부, 429면 정적 지도 일일 1,000건 한도
```

카카오 로드뷰 존재 여부와 스카이뷰 표시는 JS SDK 전용이라 curl로 확인할 수 없다. 아래 B1(브라우저)로 확인한다.

### 네이버 (N-S1~N-S2)

```bash

  -H "x-ncp-apigw-api-key: $NCP_MAPS_CLIENT_SECRET" \

  --data-urlencode "level=16" \
  --data-urlencode "w=400" \
  --data-urlencode "h=300" \
  --data-urlencode "maptype=satellite" \
  -o /dev/null -w "%{http_code} %{content_type}\n"
# 응답에서 확인할 것: 200 과 image/jpeg(기본 format=jpg). 오류면 Application에 Static Map이 등록됐는지, VPC 환경인지
```


## 7. 이 영역 추천안

- 1순위: **카카오맵 지도 Web API — 스카이뷰(현재 위성) + 로드뷰를 JS SDK로 실시간 표시**. 종합 확신도: `미확인` (필수 항목 "커버리지"에 공식 문서가 없다. 그 밖의 필수 항목은 `부분 확인`). 이미지를 저장하지 않고, 로고·저작권 표시를 가리지 않으며, "촬영 시점 미제공"으로 표기하는 것이 전제다.
- 대안:
  - 로드뷰에 촬영일이 꼭 필요하면 **네이버 거리뷰**(`photodate`, 종합 `미확인`)를 쓴다. 단 장소 검색은 카카오 그대로 쓰고, 네이버 약관의 즉시 1회 사용 조건을 지킨다.
  - 그때/지금 비교의 "지금" 쪽을 라이선스가 가장 단순한 출처로 하려면 **브이월드 WMTS 영상**(종합 `미확인`)을 쓴다. B8 확인 뒤에 판단한다.
  - **Google**(종합 `부분 확인 (PM 호출 대기)`)은 장소 검색·지도·로드뷰를 모두 Google로 통일하고 그때 사진을 같은 화면에 두지 않을 때만 쓴다.
- 이유:
  1. 장소 검색 1순위(T1 카카오 로컬)와 같은 콘솔·앱을 쓴다. 무료 한도도 지도 Web SDK가 하루 300,000건으로 가장 크다 [6].
  2. 공식 문서에서 다른 이미지와 함께 표시하는 것을 막는 조항을 찾지 못했다 [7][8]. 지도 위에 HTML 콘텐츠를 올리는 것을 기능으로 안내한다 [3]. Google은 반대로 "Google 지도에만 표시" 요약 [25]과 비Google 지도 금지 조항 단서 [S3]가 있다.
  3. 브라우저 키 설정이 단순하다. JavaScript 키에 도메인을 등록하면 되고, `localhost` 예가 문서에 있다 [1].
  4. 약점은 촬영일이 없다는 점이다 [2]. 6.1절 원칙에 따라 "현재 모습(촬영 시점 미제공)"으로 정직하게 표기하는 것으로 보완한다(D2).
  5. 확인됨으로 올리려면 B1·B3(커버리지와 레퍼런스 본문), K-S1, D5(스크린샷·캐시 해석)가 필요하다.

**같은 회사로 묶을 때의 장단점 (T1 `place-search.md` 7절에서 이어받음)**: **카카오로 묶으면** 장소 검색(REST 키)과 지도·로드뷰(JavaScript 키)를 한 앱에서 관리한다. 두 키는 섞어 쓰면 안 된다 [4]. 무료 쿼터가 처음 활성화한 앱에만 있으므로 [4], 한 앱에 모으는 것이 비용 면에서도 유리하다. 단점은 로드뷰·위성 촬영일이 없다는 점과, 한 회사의 정책 변경(2026-07-21 같은 사용 방식 변경 [4])에 동네 섹션 전체가 함께 흔들린다는 점이다. **Google로 묶으면** 촬영일(Street View)과 서버 측 사전 확인이 가장 좋다. 그러나 T1 D3("결과는 Google 지도에")와 이 문서 D4(비Google 이미지와 같은 화면)가 겹친다. 그래서 국가 항공사진과 나란히 놓는 그때/지금 비교 자체가 막힐 수 있다. 무료 한도도 가장 작다. **네이버로 묶으면** 지도·위성·거리뷰(촬영일)·행정동 코드는 한 회사에서 받지만, 장소 이름 검색이 없다(T1). 저장 금지 조항도 가장 엄격하다. 결론적으로 **카카오로 묶는 구성(장소 검색 + 지도·스카이뷰·로드뷰)을 추천**한다. 촬영일 표기가 꼭 필요하면 로드뷰만 네이버로 바꾸는 혼합안을 검토한다(D1). 장소 결과 좌표를 네이버 거리뷰에 넘기는 것은 카카오 포럼 답변상 실시간이면 문제없다는 단서가 있지만 [S2], 공식 근거는 아니다.

## 8. 위험

1. **"현재 모습"이 실제로는 몇 년 전 사진일 수 있다.** 카카오와 모든 위성 출처는 촬영일을 주지 않는다 [2][12][24][31]. `현재 모습` 이라고만 쓰면 6.1절의 정직한 날짜 표기 원칙과 어긋날 수 있다(D2).
2. **이미지를 저장할 수 없어 다른 기능과 테스트에 영향이 있다.** 세 회사 모두 저장·캐시를 막거나 좁게 허용한다 [7][16][18][25]. 결과 화면을 다시 열 때마다 SDK·API를 다시 불러야 하고, 공유용 이미지(10절 아이디어)는 지도·로드뷰 화면을 담을 수 없다. 테스트에서도 SDK가 그린 화면을 fixture로 녹화하기 어렵다. 테스트는 SDK를 스텁으로 바꿔야 한다(T1 D2와 같은 결론).
3. **브라우저 키가 필수다.** 카카오 JavaScript 키, 네이버 Client ID, Google 브라우저 키는 브라우저에 노출된다 [1][13][26]. 제품 정의서 8절이 예외로 허용하지만, 도메인 제한을 빠뜨리면 다른 사이트가 쿼터를 쓸 수 있다. 카카오는 무료 쿼터가 첫 앱에만 있어 [4], 쿼터를 도용당하면 바로 비용이 생긴다.
4. **공식 문서를 일부 읽지 못했다.** 카카오 레퍼런스 본문 [2], Google 약관 본문 [29][30], 네이버 약관 현행판·요금표 [16], 브이월드 가이드·약관 [34]. 특히 Google의 비Google 지도 조항은 단서만으로 판단했다.
5. **로드뷰 존재 여부를 서버에서 미리 알 수 없다(카카오·네이버).** 두 회사의 파노라마 찾기는 JS 전용이다 [2][11]. 그래서 결과 화면이 로드뷰 칸을 먼저 띄운 뒤 "로드뷰 없음"으로 바꾸는 흐름이 필요하다. Google만 서버에서 무료 메타데이터로 미리 확인할 수 있다 [17].
6. **Google 파노라마 ID 저장 문구가 문서마다 다르다.** 정책은 무기한 저장을 허용하고 [18], 요청 문서는 저장하지 말라고 한다 [19]. Google을 쓰게 되면 저장하지 않는 쪽으로 설계하는 것이 안전하다.
7. **Embed API는 광고를 띄울 수 있다** [22]. 생일 이야기 화면의 톤(6.3절)과 맞지 않을 수 있다.
8. **문서가 자주 바뀐다.** 카카오는 2026-07-21에 사용 방식을 바꿨고 [4], 쿼터·요금은 바뀔 수 있다고 적었다 [6]. Google 문서는 2026-10-07~09에 갱신됐다 [17][25]. 구현 직전에 다시 확인해야 한다.

## 10. PM 결정 필요

아래 결정은 다음 M0 작업(T4~T6)을 막지 않는다. T6 `summary.md` 6절에 모아 한 번에 결정한다.

**D1. 지도·로드뷰 제공자** (관련: 13절 "지도·로드뷰 제공자", 로드맵 M4)
- 근거: 7절 제공자 비교표, T1 `place-search.md` 7절.
- 선택지:
  - (a) 카카오로 통일(장소 검색 + 스카이뷰 + 로드뷰).
  - (b) 카카오(장소 검색 + 스카이뷰) + 네이버 거리뷰(촬영일 표기용).
  - (c) Google로 통일(장소 검색 + 위성 + Street View). 그때 사진은 같은 화면에 두지 않는다.
- 추천안: (a). 촬영일 표기가 꼭 필요하다고 판단되면 M4 계획 때 (b)를 다시 본다.

**D2. 촬영일을 모르는 "지금" 이미지의 표기** (관련: 6.1절, 6.2절 `date_precision`)
- 근거: 카카오·위성 출처에 촬영일 없음 [2][12][24], Google Street View는 연·월 [17].
- 선택지:
  - (a) `date_precision: current` 를 유지하되, 화면 문구를 "현재 모습(촬영 시점 미제공)"으로 한다. 촬영일을 아는 출처는 `month`/`year` 로 "2023년 5월 촬영"처럼 쓴다.
  - (b) `date_precision` 에 `unknown` 같은 새 값을 추가하고, `current` 는 촬영일이 최근으로 확인된 경우에만 쓴다.
  - (c) 촬영일을 주는 출처만 쓴다(사실상 로드뷰는 Google·네이버, 위성은 쓸 수 없음).
- 추천안: (a). 제품 정의서 6.1절 문구에 "제공자 최신 이미지, 촬영 시점 미제공"을 추가하는 것을 PM이 검토한다.

**D3. SDK로 그리는 미디어의 `url`·`thumbnail_url` 처리** (관련: 6.2절, `CLAUDE.md` 7절 1항, M4)
- 근거: SDK 렌더링, 이미지 저장 금지 [2][11][16][18].
- 선택지:
  - (a) `url` 에 내부 렌더 URI(예: 제공자·좌표·줌·파노라마 ID를 담은 문자열)를 넣고, 요청마다 만들며 저장하지 않는다.
  - (b) 6.2절을 고쳐 `streetview`·`satellite` 타입은 `url`·`thumbnail_url` 대신 `render` 필드(제공자, 좌표, 줌 등)를 필수로 한다.
- 추천안: (b). 필수 필드 규칙의 뜻(출처·라이선스·시점이 없는 미디어를 보여주지 않는다)을 지키면서 SDK 미디어를 다룰 수 있다. M4 계획 때 확정한다.

**D4. 지도·로드뷰 이미지를 다른 회사 이미지(국가 항공사진)와 같은 화면에 두는 것** (관련: 5절 2번, T1 D3)
- 근거 위치: Google Maps JavaScript API 정책의 "results must be displayed on Google Maps" [25], 서비스 약관 3.2.3(e)(본문 미확인, 단서 [S3]), 네이버 Maps 이용약관 제7조 ⑨항 "가공" [16], 카카오 플랫폼 서비스 약관 제11조 ② 9호 "수정" [8].
- 선택지:
  - (a) Google은 동네 섹션에 쓰지 않는다. 카카오·네이버는 나란히 보기(겹치지 않음)로만 쓴다.
  - (b) Google을 쓰려면 PM이 B6에서 약관 원문을 확인한 뒤 정한다.
  - (c) 그때 사진과 지금 이미지를 다른 화면(다른 카드)으로 분리한다.
- 추천안: (a). 이 판단은 법률 자문이 아니다.

**D5. 지도·로드뷰 화면의 캡처·저장 범위** (관련: 8절 캐시, 10절 아이디어 "공유용 카드", `CLAUDE.md` 7절 5항)
- 근거 위치: 카카오 운영정책 제5조 20·30호 [7], 플랫폼 서비스 약관 제11조 ③·② 9호 [8], 네이버 Maps 이용약관 제7조 ⑨·⑪ [16], Google 정책의 캐시 제한 [18][25].
- 묻는 것: 스크린샷이나 썸네일 저장이 "복사·저장"에 해당하는가. 테스트용 화면 스냅숏을 저장소에 넣어도 되는가.
- 선택지:
  - (a) 어떤 형태로도 저장하지 않는다. 테스트는 SDK 스텁으로 하고, 공유 카드에는 지도·로드뷰를 넣지 않는다.
  - (b) 제공자(카카오)에 앱 계정으로 공식 문의한 뒤 정한다.
- 추천안: (a). 공유 카드를 마일스톤에 넣을 때 (b)를 한다. 이 판단은 법률 자문이 아니다.

**D6. 브라우저 키 예외의 범위** (관련: 8절, `.env.example` 은 M1에서 backend-dev가 추가)
- 근거: 카카오 JavaScript 키 [1], 네이버 Client ID(`ncpKeyId`) [13], Google 브라우저 키 [26].
- 선택지:
  - (a) D1에서 고른 제공자의 브라우저 키 하나만 예외로 허용한다(예: `VITE_KAKAO_JS_KEY`, 운영 도메인과 `localhost` 등록).
  - (b) 후보 제공자 키를 모두 예외로 허용한다.
- 추천안: (a).
