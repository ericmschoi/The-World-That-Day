핵심:
- 1순위 중 지금 `확인됨` 인 것은 **그날의 사건(Wikimedia 계열)** 과 **서울 기록 사진(서울역사아카이브, 사진으로 본 서울)** 뿐이다 ([T5 7절](day-events.md#7-이-영역-추천안), [T4 7절](archive-media.md#7-이-영역-추천안)). 장소 검색·항공사진·위성·로드뷰 1순위는 모두 PM 확인 명령이나 브라우저 확인, 결정을 기다린다(2절).
- 과거 항공사진은 API가 없고 2010년 이전 촬영분은 정사영상으로 제공되지 않아(문서 기준, 정사영상원시영상 시간범위 1947~2025년과의 충돌은 T2 B3로 확인), 제품 정의서의 "그때/지금 슬라이더"는 큐레이션 지점의 나란히 보기로 줄어든다 ([T2 1절](aerial-imagery.md#1-요약)).
- 화면에 바로 쓸 수 있는(제1유형이 자료마다 확인된) 기록 사진은 서울에만 있다 ([T4 1절](archive-media.md#1-요약)).

## 4. PM이 키 발급 후 실행할 확인 명령

공통 규칙 (영역 문서 6절과 같음): 키는 `$ENV_VAR` 로만 넣는다. 응답 원문, 이미지, 내려받은 파일은 저장소에 넣지 않는다. "응답에서 확인할 것"의 값만 data-researcher에게 넘겨 주면 새 커밋으로 확신도를 올린다. 쿼리는 데모 장소(와 T1의 "중앙병원")만 쓴다. 명령 원문은 링크한 영역 문서 6절에 있다.

### 4.1 실행 순서 제안

로드맵의 선행 조건 기준으로 막고 있는 것부터 적었다.

1. **M2a 전**: T1 K1~K6(카카오 로컬), T1 R1(법정동코드 전체 목록 받기, 2026-10-27 D1~D2를 대체). 로드맵 M2의 선행 조건 "장소 검색 1순위 출처가 확인됨"을 채우는 데 필요하다 — [T1 7절](place-search.md#7-이-영역-추천안), [로드맵](../roadmap.md).
2. **M3a 전**: 없음. 그날의 사건 1순위는 공개 엔드포인트로 확인을 마쳤다 — [T5 6절](day-events.md#6-pm이-실행할-확인-명령). M3c를 넣기로 하면 T5 A1·A2와 T4 B1.
3. **M4 계획 전**: 브라우저 확인 1·13·15(항공사진 연도 목록, 카카오 로드뷰·스카이뷰, 카카오 레퍼런스)와 T3 K-S1. 조합 B를 검토하려면 브라우저 확인 4.
4. **M5 계획 전**: T4 A1~A3, 브라우저 확인 16~24.
5. **Google·네이버를 고를 때만**: T1 G1~G4·N1~N4, T3 G1~G2·N-S1~N-S2, 브라우저 확인 7~10.

### 4.2 키가 필요한 명령 (영역별)

"명령 D1~D2"는 T1 6절의 명령 번호이고 T1 10절의 결정 D1~D5와 다르다.

### 7.2 그 밖에 로드맵에서 바뀌는 것 (planner 입력)

- **M2a**: 선행 조건 "장소 검색 1순위 출처가 확인됨"이 아직 채워지지 않았다(카카오 로컬 `부분 확인 (PM 호출 대기)`). K1~K6 실행과 #11 결정이 M2a 전에 필요하다. 법정동코드는 2026-10-27 결정 #10 (a)로 확인됨이 되었고, 지역 사전 원천 파일은 R1로 받는다. 범위의 "약관이 허용하면 캐시"는 지역 사전 + 실시간 호출로 바뀌고, ★ PM 직접 구현 후보 "장소 해석 결과 캐시 엔티티"는 다시 정해야 한다. `data/regions.json` 의 원천은 법정동코드 API다 — [T1 7절](place-search.md#7-이-영역-추천안), [T1 8절](place-search.md#8-위험).
- **M3를 먼저 시작할 수 있다**: 그날의 사건 1순위는 모두 `확인됨` 이고 키가 필요 없다(User-Agent만). 로드맵 "순서를 이렇게 정한 이유" 3번의 가정이 맞았다. M3a의 공용 미디어 형식에 #17·#18 결과와 Commons 비자유 이미지 거르기(`NonFree`, `imagerepository`, `pilicense=free`)를 넣는다. M3 완료 기준(1988-09-17 서울 올림픽 개막)은 한국어 위키백과로 채울 수 있다 — [T5 7절](day-events.md#7-이-영역-추천안), [T5 5절](day-events.md#5-데모-입력-판단).
- **M4a**: 로드맵 위험 1이 현실이 됐다(과거 항공사진 API 없음, 2010년 이전 촬영분은 정사영상으로 제공되지 않음 — 문서 기준, T2 B3로 확인). "항공사진 어댑터"는 외부 API가 아니라 큐레이션 데이터(PM 신청 + content-curator 기록)를 읽는 것이 된다. "그때/지금 비교 슬라이더"와 완료 기준은 "나란히 보기"로 고친다. ★ 후보 "항공사진 근접 연도 선택과 외부 호출 타임아웃·장애 격리"에서 외부 호출 부분은 현재 영상(카카오 SDK) 쪽만 남는다. 과거 쪽은 #9 답이 오기 전까지 `link_only` 다 — [T2 7절](aerial-imagery.md#7-이-영역-추천안), [T3 7절](satellite-streetview.md#7-이-영역-추천안).
- **M4b**: 로드뷰는 현재 모습만 가능하고 카카오는 촬영 시점을 주지 않는다. 완료 기준의 "촬영 시점 표시"는 #17 표기로 바꾼다. 카카오 로드뷰 유무는 서버에서 미리 알 수 없으므로 UI가 "로드뷰 없음"으로 바뀌는 흐름을 넣는다 — [T3 8절](satellite-streetview.md#8-위험).
- **M4c**: 서울은 "사진으로 본 서울" 큐레이션(content-curator), 서울 밖은 Commons 현재 모습과 안내다. 담당에 content-curator를 넣는다 — [T4 7절](archive-media.md#7-이-영역-추천안).
- **M5a·M5b**: 서울 명소는 서울역사아카이브(1957~1988)와 사진으로 본 서울(1995~)로 채우고, 1989~1994년은 공백이다. M5 계획 때 정할 "큐레이션 시·도 범위(서울·광주부터)"에서 광주는 제1유형 기록 사진 원천이 없다는 점을 반영한다 — [T4 8절](archive-media.md#8-위험).

## 8. 기술 스택에 영향을 주는 발견

결론: `CLAUDE.md` 0절 초안(Java 21, Spring Boot 3, PostgreSQL, Flyway, React, TypeScript, Vite 등)을 바꿀 발견은 없다. 아래는 M1 계획서에서 세부로 정할 것이다.

1. **브라우저 지도 SDK 로딩 (프론트엔드)**: 1순위 카카오맵은 JS SDK 스크립트를 넣고 `kakao` 객체를 쓴다. 가이드에 SPA 전용 안내가 없고 "객체를 쓰기 전에 스크립트를 불러오라"고만 적혀 있다. React에서 스크립트를 한 번만 불러오는 로더가 필요하다. 네이버 SDK는 `callback` 비동기 로딩을 지원한다 — [T3 2절](satellite-streetview.md#2-확인할-질문과-답) 질문 1.
2. **브라우저 키와 서버 키 분리**: 서버 키는 `VITE_` 로 시작하면 안 되고, 브라우저 키는 고른 제공자 하나만 둔다(결정 #8). Vite 환경변수 규칙과 맞는다 — 3절, 계획서 "환경변수 이름 규칙".
3. **테스트 도구**: 지도 SDK가 그린 화면은 fixture로 녹화하기 어려워 Vitest·Playwright에서 SDK를 스텁으로 바꿔야 한다. 카카오·네이버 응답은 합성 fixture를 쓴다(결정 #12). WireMock·MSW는 그대로 쓸 수 있다 — [T3 8절](satellite-streetview.md#8-위험), [T1 10절](place-search.md#10-pm-결정-필요).
4. **좌표 변환 라이브러리**: 1순위 조합(카카오 로컬 기본 WGS84, 카카오 SDK `LatLng`)에서는 따로 필요하지 않다. 브이월드 WMTS(EPSG:3857, 조합 B)를 쓸 때만 타일 좌표 변환이 필요하다 — [T1 2절](place-search.md#2-확인할-질문과-답) 질문 8, [T3 3절](satellite-streetview.md#3-출처-카드).
5. **위키텍스트 파서 (백엔드)**: 한국어 날짜 문서·연도 문서는 자유 형식 위키텍스트라 하위 줄(`**`), 링크 별칭, "사건"·"문화" 두 절을 처리하는 파서가 필요하다. 읽은 판 번호(`revid`)를 저장한다 — [T5 3절](day-events.md#3-출처-카드), [T5 8절](day-events.md#8-위험).
6. **DB와 캐시**: 장소·지도 결과는 저장할 수 없어 장소 캐시 테이블보다 지역 사전(법정동코드)이 중심이 된다. 반대로 위키백과 날짜 문서 366개와 연도 문서는 미리 받아 캐시할 수 있다(라이선스가 복제 허용). OTD를 쓰면 응답이 250~490KB라 월·일 단위 캐시가 필요하다 — [T1 8절](place-search.md#8-위험), [T5 7절](day-events.md#7-이-영역-추천안), [T5 8절](day-events.md#8-위험).
7. **외부 호출 클라이언트**: Wikimedia는 연락처가 든 User-Agent 필수, 규칙에 맞으면 분당 200회, 429와 `Retry-After` 처리, 직렬 요청을 권한다. Wikidata Query Service는 질의 60초 제한이 있고 v2 엔드포인트로 바뀔 수 있어 주소를 설정값으로 뺀다. `CLAUDE.md` 7절 3항(어댑터, 타임아웃)과 맞는다 — [T5 2절](day-events.md#2-확인할-질문과-답) 질문 7, [T5 8절](day-events.md#8-위험).
8. **큐레이션 미디어 사본 저장**: 제1유형·CC BY 사본을 Git 밖에 둔다(결정 #13). 저장 위치(로컬 디렉터리, 오브젝트 스토리지 등)와 정적 파일 제공 방식을 M1·M5에서 정한다. 제3·4유형은 #9 답 전까지 변환(썸네일 생성)하지 않는다 — [T4 10절](archive-media.md#10-pm-결정-필요), [T4 4절](archive-media.md#4-미디어-레코드-필드-매핑).
9. **조건부 항목**: Google을 고르면 Static 이미지의 서버 측 서명 구현이 필요하다 — [T3 2절](satellite-streetview.md#2-확인할-질문과-답) 질문 7. M3c를 넣으면 대한뉴스 CSV(25,404행)를 받아 `제작일` 로 색인하는 작업이 필요하다 — [T4 3절](archive-media.md#3-출처-카드).
