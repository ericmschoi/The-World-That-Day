# 기록 사진·영상 — 출처 검증

> 작업: T4 · 계획서: docs/plans/m0-source-research.md · 조사 일자: 2026-10-09 · 작성: data-researcher
> 이 문서의 약관 해석은 법률 자문이 아니다. 확신도 기준은 계획서의 "확신도 기준"을 따른다.
> 이 영역은 사이트마다 자료 페이지(HTML)에 붙은 공공누리 표시가 근거의 중심이다. 자료를 열 때 파일은 내려받지 않았고 페이지 텍스트만 읽었다. 포토코리아 검색은 도구에서 HTTP 403으로 막혔고, 국가기록원 통합검색·e영상역사관 통합검색·사진으로 본 서울 검색은 자바스크립트로 그려져 목록 페이지나 고유 주소로 들어갔다.

## 1. 요약

- **화면에 바로 쓸 수 있는(공공누리 제1유형, 자료마다 표시가 확인된) 기록 사진은 서울에만 있다.** 서울역사아카이브(서울시정사진 1957~1988년이 웹에 공개, 자료 8건 모두 제1유형 [21][24]~[31])와 서울연구원 "사진으로 본 서울"(서울경관 기록화 사진 1995~2020년, 자료 6건 모두 제1유형 + CC BY 4.0 [68]~[74])이다. 둘 다 API가 없어 **미리 골라 두는 큐레이션 용도**다. 종합 확신도는 둘 다 `확인됨`.
- **전국 자료와 "같은 날" 자료는 e영상역사관(KTV)에 있지만 사진은 공공누리 제4유형(상업 금지·변경 금지)이고, 대한뉴스 영상은 공공누리 표시가 없어 사전 협의 대상이다** [35][43]~[48]. 데모 날짜 3개 중 1988-09-17(올림픽 개막식)과 2002-06-22(광주 월드컵경기장 응원)는 같은 날 사진이, 1995-03-15는 같은 달 사진(1995-03-01 중앙청 철거식)이 있다. 상업화하면 이 사진들은 쓸 수 없다.
- **같은 자료의 라이선스 표기가 경로마다 다르다.** 공공데이터포털의 e영상역사관 파일데이터는 "이용허락범위 제한 없음"인데 [51][52], 같은 사진의 자료 페이지는 제4유형이다 [43]. T2의 D2(형식의 변경 포함 문제 [85])와 같은 성격이라 썸네일·리사이즈 허용도 같은 문제를 안는다(10절 D2, D3).
- 국가기록원은 키로 부르는 검색 API가 있지만 응답에 생산연도만 있고 썸네일·라이선스·장소 필드가 없으며 [1], 1988년 이후 사진에는 공공누리 표시를 찾지 못했다(`link_only`). TourAPI는 공공누리 제1·3유형 사진을 주지만 대부분 현재 관광 사진이라 "그때" 용도로는 맞지 않는다 [59][60].
- 제품 정의서 가정과 다른 점: 7절의 "특정 동네를 그날 찍은 사진은 대부분 없다"는 맞다. 다만 큰 행사가 있던 날은 같은 날 사진이 있다. 반면 5절 "그 도시의 풍경"은 **서울 밖에서 화면에 직접 보여 줄 수 있는 기록 사진이 거의 없다**(9절).

## 2. 확인할 질문과 답

질문 번호는 계획서 "T4 작업별 기준"의 번호다. 제품 정의서 7절 "M0에서 확인할 것" 4개(검색 API 유무, 날짜·장소 메타데이터 수준, 공공누리 유형, 영상 임베드 가능 여부)는 질문 열에 `(7절)` 로 표시했다. 출처 약칭:

- **국가기록원**: 국가기록원 기록물 검색(나라기록물 검색 OpenAPI, 웹 검색, 주제 콘텐츠 `theme.archives.go.kr`)
- **서울역사아카이브**: 서울역사박물관 서울역사아카이브
- **e영상역사관**: 한국정책방송원(KTV) e영상역사관 웹사이트
- **공공데이터포털**: 공공데이터포털에 등록된 이 영역 데이터셋(주로 e영상역사관 파일데이터와 그 자동 생성 API)
- **TourAPI**: 한국관광공사 국문 관광정보 서비스(이미지정보)와 관광사진 정보(포토코리아)
- **사진으로 본 서울**: 서울연구원 서울연구데이터서비스 "사진으로 본 서울" (추가 후보)
- **Commons**: Wikimedia Commons 위치 기반 검색 (추가 후보)

- **TourAPI**: 비상업·상업 모두 제1유형은 `embed`, 제3유형은 원본을 변경 없이 보여 줄 수 있을 때만 `embed` [59][85]. 이용약관(B4) 확인 전까지는 잠정이다.
- **e영상역사관 사진(공공데이터포털 이미지 포함)**: 비상업일 때 D2(축소 표시가 변경인지)와 D3(데이터셋 "제한 없음"과 자료 페이지 제4유형 중 무엇을 따르나)가 허용으로 정해져야 `embed`. 그 전에는 `link_only`. 상업일 때는 `link_only` [84][85].
- **e영상역사관 대한뉴스 영상**: 비상업·상업 모두 `link_only` (사전 협의 대상 [35]). 나누리 이용 조건(B2)과 PM 결정(D1)에 따라 바뀔 수 있다.
- **국가기록원**: 비상업·상업 모두 `link_only` (공공누리 표시 없음 [4][5]).

## 6. PM이 실행할 확인 명령

공통 규칙: 키는 `$DATA_GO_KR_SERVICE_KEY` (공공데이터포털 서비스 키, 서버 전용, `VITE_` 없음)로만 쓴다. 응답 원문과 내려받은 파일은 저장소에 넣지 않고, "확인할 것"의 값만 data-researcher에게 넘긴다. 쿼리는 데모 장소만 쓴다.

### 키가 필요한 명령

**A1. 나라기록물 검색 OpenAPI** — 문서의 키 이름이 `key`(요청변수 표)와 `serviceKey`(URL 예시)로 다르므로 두 번 실행한다.

```bash
# 근거: https://www.archives.go.kr/next/newsearch/openAPI01.do (요청 URL 예시는 serviceKey)
curl -sS -G "https://search.archives.go.kr/openapi/search.arc" \
  --data-urlencode "serviceKey=$DATA_GO_KR_SERVICE_KEY" \
  --data-urlencode "query=서울대학교병원" \
  --data-urlencode "rc_type=ritem" \
  --data-urlencode "display=10" | head -c 3000
# 응답에서 확인할 것: total, 각 item의 title, prod_year, doc_type(C=사진·필름, D=동영상), online_reading, link.
#   오류 1001(등록되지 않은 인증키)이면 아래 key 이름으로 다시 실행.

# 근거: 같은 문서의 요청변수 표 (key)
curl -sS -G "https://search.archives.go.kr/openapi/search.arc" \
  --data-urlencode "key=$DATA_GO_KR_SERVICE_KEY" \
  --data-urlencode "query=광주 서구 풍암동" \
  --data-urlencode "rc_type=ritem" \
  --data-urlencode "display=10" | head -c 3000
# 응답에서 확인할 것: 어느 키 이름이 통하는지, total 건수, doc_type이 C·D인 건이 있는지,
#   응답 어디에도 썸네일·라이선스·장소 필드가 없는지(문서와 같은지).
```

## 7. 이 영역 추천안

용도별로 나눈다. 두 용도 모두 API가 아니라 **content-curator가 `data/` 에 미리 골라 두는 방식**이 중심이다.

**M4c 동네 곳곳 사진**
- 1순위: **서울연구원 "사진으로 본 서울"** (종합 확신도: `확인됨`). 서울 동네의 1995~2020년 사진을 월 단위 날짜, 제1유형 + CC BY 4.0으로 보여 줄 수 있다 [65][68]. 데모 "서울대학교병원"(1995)에 1차 사진이 있을 가능성이 높다(B5로 확인).
- 대안: **Wikimedia Commons 위치 기반 검색** (`확인됨`) — 라이선스 필드로 자동 필터가 되지만 데모 지점에 ±5년 사진이 없었다 [79][80]. "현재 모습" 보조로만 쓴다. 서울 밖에서 "그때" 사진이 필요하면 e영상역사관 사진(`부분 확인`, 비상업 + D2 허용일 때만)이 남는다.
- 이유: 서울 밖 동네의 1980~2000년대 사진을 제1유형으로 주는 출처를 찾지 못했다. 그래서 **서울 밖 동네 곳곳은 대부분 "현재 모습"이 되거나 비게 된다**(D5).

**M5 대표 명소 기록 미디어**
- 1순위: **서울역사아카이브** (종합 확신도: `확인됨`) — 서울 대표 명소의 1957~1988년 사진, 일 단위 `시기`, 제1유형 [21][22]. 데모 "서울"(1988)에 같은 달 사진이 있다 [31].
- 대안 1: **e영상역사관 국가기록사진·대한뉴스** (`부분 확인`) — 전국, 일 단위, 데모 3개 모두 같은 날·같은 달 자료가 있다. 사진은 비상업 + D2·D3 허용일 때만 `embed`, 대한뉴스는 `link_only`.
- 대안 2: **사진으로 본 서울**(1995년 이후 서울 명소), **TourAPI**(`부분 확인 (PM 호출 대기)`, 명소의 현재 모습).
- 이유: 서울은 1988년까지 서울역사아카이브, 1995년부터 사진으로 본 서울로 제1유형 자료가 이어진다(1989~1994년은 공백). 서울 밖 명소는 제1유형 기록 사진 원천이 없어 e영상역사관(제4유형)에 기대야 하므로 상업화 결정의 영향을 가장 크게 받는다.

**보조(T5와 공유)**: 공공데이터포털의 대한뉴스관·국가기록사진 파일은 날짜(`제작일`)로 "같은 날" 후보를 미리 찾는 색인 원천이다(`부분 확인 (PM 호출 대기)`). 국가기록원 API는 링크 카드용 메타데이터만 준다(`부분 확인 (PM 호출 대기)`).

## 8. 위험

1. **상업화하면 서울 밖 기록 사진이 거의 사라진다.** e영상역사관 사진은 표본 전부 제4유형이고 [43]~[48], 제4유형은 영리와 간접적으로 관련된 이용도 금지한다 [85]. 광고를 붙이는 것도 해당할 수 있다(D2와 함께 PM 판단).
2. **같은 자료의 라이선스 표기가 경로마다 다르다.** 공공데이터포털 "제한 없음" [51][52] 대 자료 페이지 제4유형 [43]. 느슨한 쪽을 따르면 나중에 문제가 될 수 있다(D3).
3. **메타데이터 품질.** 서울역사아카이브의 `시기` 가 도록 발행 연도로 들어간 사례가 있다 [26]. e영상역사관에서 같은 날 같은 경기를 다룬 두 사진 중 한 자료는 설명에 "4강전"이라 적었고 [44], 같은 사이트의 2002.06.25 자료는 "월드컵 4강전(한국vs독일)"이라 적는다 [42]. 설명을 그대로 화면에 쓰면 사실과 다른 문구가 나갈 수 있다. 큐레이션 때 날짜·설명을 사람이 확인해야 한다(6.1절 정직한 날짜 표기).
4. **API가 없는 출처가 1순위다.** 서울역사아카이브와 사진으로 본 서울은 웹 페이지뿐이다. 사이트 개편으로 주소가 바뀔 수 있다(실제로 2021년 안내의 "서울 경관 아카이브" `urban.seoul.go.kr/cityscape` 는 지금 404다 [75][76]).
5. **핫링크 허용 여부를 모른다.** 어느 기관 문서에도 핫링크 조항이 없다. 사본을 두면 저장소·서버 용량과 출처 표시 관리가 필요하다(D6).
6. **대한뉴스 영상은 아직 어떤 형태로도 화면에 직접 넣을 근거가 없다.** 공공누리 표시가 없고 사전 협의 대상이다 [35]. KTV가 2025년에 영상 저작물을 개방했다는 보도와 블로그가 있으나 [S2][S3] 공식 이용 조건은 나누리 로그인 뒤에 있어 읽지 못했다(B2).
7. **국가기록원 자료는 1988년 이후 공공누리 표시가 없다** [5][9]~[16]. 링크 카드에 썸네일도 없다 [1].
8. **서울 1989~1994년 공백.** 서울역사아카이브 웹 목록은 1988년까지, 사진으로 본 서울은 1995년부터다 [22][66]. 이 기간 출생자의 서울 명소 기록 사진은 e영상역사관에 기대게 된다.
9. **T2에서 넘어온 단서 확인 결과.** (1) 서울시 1995~2025년 반복 촬영 사진(Korea Times [S1])은 서울경관 기록화 사업으로 공식 확인했고 추가 후보 카드로 썼다 [66]. 다만 7차(2024~25년 무렵) 사진의 온라인 공개 여부는 확인하지 못했다. (2) 국가기록원 항공사진기록 [S5]은 국가기록원 공식 페이지를 찾지 못해 `미확인` 이다.

## 10. PM 결정 필요

아래 결정은 다음 M0 작업(T5~T6)을 막지 않는다. T5가 참조할 e영상역사관 카드의 회차·날짜 메타데이터는 확인되어 있다. T6 `summary.md` 6절에 모아 한 번에 결정한다. 이 판단들은 법률 자문이 아니다.

**D1. 대한뉴스 영상 처리 방식** (관련: 13절 "영상 처리 방식", M3c·M5)
- 근거 위치: e영상역사관 저작권 정책의 "공공누리 미표시 영상은 사전 협의" [35], 자료 페이지의 "KTV 나누리를 통해 신청" [38].
- 선택지:
  - (a) e영상역사관 꼭지 페이지로 `link_only`. 제목·회차·날짜만 텍스트로 보여 준다.
  - (b) PM이 B2(나누리 이용 조건)를 확인하고, 허용되면 데모 날짜 꼭지만 신청해 받은 영상을 짧게 보여 준다.
  - (c) 영상을 쓰지 않는다.
- 추천안: (a). B2에서 공공누리 제1유형 같은 명시 조건이 확인되면 (b)를 다시 본다.

**D2. 제4·3유형 사진의 썸네일·리사이즈가 "변경"인지** (관련: 6.2절, 13절 "상업적 이용 여부", T2 `aerial-imagery.md` 10절 D2)
- 근거 위치: 공공누리 유형 안내의 "형식의 변경" 포함 문구 [85], 제4유형 안내 [84], 제3유형 안내(T2 [21]), e영상역사관 사진 제4유형 표시 [43]~[48], TourAPI 제3유형 표기 [59].
- 묻는 것: 원본 비율을 지킨 축소 표시, 웹용 형식 변환, 화면 맞춤 자르기가 변경금지에 걸리는가. 제4유형의 "간접적 영리"에 광고 게재가 포함되는가.
- 선택지:
  - (a) T2 D2 문의 때 함께 문화체육관광부 콘텐츠기획과(사진 문의처 [35])에 서면으로 묻는다.
  - (b) 가장 엄격하게 보고 제3·4유형은 `link_only` 로만 쓴다.
  - (c) 비상업 + 원본 비율 축소만 허용으로 보고 `embed` 한다.
- 추천안: (a). 답을 받기 전까지 (b)로 설계한다.

**D3. 공공데이터포털 "제한 없음"과 자료 페이지 공공누리 표기가 다를 때 무엇을 따르나** (관련: 6.2절, T1 `place-search.md` D4)
- 근거 위치: 대한뉴스관·국가기록사진 데이터셋의 이용허락범위 [51][52], 국가기록사진 `저작권` 열 [54], 자료 페이지 제4유형 [43].
- 선택지: (a) 항상 더 엄격한 자료 페이지 표기를 따른다, (b) 데이터셋 표기는 메타데이터에만 적용된다고 보고 이미지는 자료 페이지를 따른다, (c) 한국정책방송원에 문의한다.
- 추천안: (a) 또는 (b) — 결과는 같다(이미지는 자료 페이지 기준). A3로 `저작권` 열 값이 자료 페이지와 같은지 확인한다.

**D4. 국가기록원 표시 없는 기록물** (관련: 13절 "상업적 이용 여부", M3c·M5)
- 근거 위치: 저작권정책 [4], 소식지 제79호의 "정보공개청구를 통한 이용허락 검토 요청 절차" [5], 온라인 사본신청 [7].
- 선택지: (a) `link_only` 로만 쓴다, (b) 데모 자료 몇 건만 정보공개청구로 이용허락을 받는다(PM 작업, 최소 2주 [7]).
- 추천안: (a).

**D5. 서울 밖 "동네 곳곳"과 "그 도시의 풍경"의 공백 처리** (관련: 5절 2·3번, 로드맵 M4c·M5, T2 D1)
- 근거: 제1유형 기록 사진 원천은 서울에만 있다 [22][66]. Commons는 데모 지점에 ±5년 사진이 없었다 [79][80].
- 선택지:
  - (a) 서울 밖은 동네 곳곳 섹션을 "현재 모습"(Commons·TourAPI)으로만 채우고, 그때 사진이 없다고 정직하게 안내한다.
  - (b) 비상업으로 정하고 e영상역사관 제4유형 사진(D2 허용 시)을 큐레이션해 채운다.
  - (c) 서울 밖은 섹션을 비운다.
- 추천안: (a). 비상업으로 정해지고 D2가 허용되면 데모 "광주 서구 풍암동"만 (b)를 더한다.

**D6. 기록 사진을 핫링크할지, 사본을 둘지** (관련: 8절 캐시, `CLAUDE.md` 7절 1·2항)
- 근거: 서울역사아카이브·사진으로 본 서울·e영상역사관 모두 핫링크 조항이 없다 [21][35][68]. 제1유형은 온·오프라인 공유를 허용한다 [83]. Commons는 핫링크를 권장하지 않는다 [77].
- 선택지:
  - (a) PM이 큐레이션 대상 사진을 직접 내려받아 우리 저장소(저장 위치는 M1·M5에서 정함)에 두고 출처를 표시한다. Git 저장소에는 넣지 않는다.
  - (b) 원 기관의 이미지 주소를 그대로 쓴다(핫링크).
  - (c) 기관에 핫링크 허용 여부를 문의한 뒤 정한다.
- 추천안: (a). 제1유형·CC BY 자료에만 적용한다.
