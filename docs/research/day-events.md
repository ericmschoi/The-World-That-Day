# 그날의 사건 + 국내 사건 보강 — 출처 검증

> 작업: T5 · 계획서: docs/plans/m0-source-research.md · 조사 일자: 2026-10-09 · 작성: data-researcher
> 이 문서의 약관 해석은 법률 자문이 아니다. 확신도 기준은 계획서의 "확신도 기준"을 따른다.
> 실제 응답은 모두 키 없이 WebFetch로 받았고, 미디어 파일은 내려받지 않았다. 응답이 100,000자를 넘는 On this day 응답은 앞 100,000자만 읽었다. 항목이 연도 내림차순으로 나오고(관찰), 읽은 구간이 데모 연도를 지나 더 이른 연도까지 내려갔으므로 데모 연도 항목 수 판단에는 영향이 없다. 건수는 WebFetch 요약 결과라 1~2건 오차가 있을 수 있다. 위키백과 문서는 이 영역의 **데이터 출처(조사 대상)** 로만 다뤘고, 사실의 근거로 쓰지 않았다. 국내 사건 보강 출처의 접근 방법·인증·라이선스는 T4 `docs/research/archive-media.md` 카드를 따르고, 여기서는 날짜축만 새로 답한다. 이 문서에서 `T4 [n]` 은 그 문서 11절의 번호다.

## 1. 요약

- **제품 정의서가 기대한 "On this day API"는 한국어를 지원하지 않고, 영어 응답에도 데모 날짜의 한국 사건이 없다.** On this day가 켜진 위키백과는 14개 언어이고 한국어는 없다(`ko` 요청은 404) [3][4][5]. 영어 응답에서 데모 연도 항목은 1988-09-17이 0건, 2002-06-22가 1건(이란 지진), 1995-03-15가 0건이다. 서울 올림픽 개막도 한국-스페인 8강전도 없다 [6]~[11]. 이 API는 "2026년 7월부터 점진적 지원 중단 예정, 대체 경로 미정"이라고 공식 문서에 적혀 있다 [1].
- **12절 기대 사건(1988-09-17 서울 올림픽 개막)은 한국어 위키백과 날짜 문서·연도 문서, Wikidata, Commons에서 나온다** [25][28][33][36][50]. 2002-06-22 한국-스페인전은 한국어 날짜 문서의 "사건"이 아니라 "문화" 절에 있고 [34], Wikidata에는 팀 이름 없이 "2002 FIFA World Cup Match 59"로만 있다 [26][29]. 1995-03-15는 어느 출처에도 국내 사건이 없다 [27][35][38][70].
- **1순위는 한국어 위키백과 날짜 문서 + 연도 문서(Action API, `확인됨`)** 다. Wikidata 날짜 질의(`확인됨`)는 사건 식별자(QID), 교차 확인, `tone` 신호용으로 함께 쓰고, 사건 대표 이미지는 Commons(`확인됨`)에서 라이선스 필드로 거른다. 영어 위키백과 대표 이미지에는 비자유(공정 이용) 이미지가 섞인다. REST 요약 응답은 이를 거르지 않지만, PageImages의 `pilicense=free` 와 `extmetadata.NonFree` 로 거를 수 있다 [48][62][63][65].
- **국내 사건 보강은 MVP(M3c)에 넣을 가치가 낮다.** 국가기록원 OpenAPI는 생산연도만 주고 날짜로 검색할 수 없다 [67]. 날짜 단위 연표는 웹 페이지뿐이다 [69]. 대한뉴스는 1994-12-31 제2040호로 끝나 1995·2002 데모에는 없다 [72]. 회차 날짜도 주간 발행일이라 6.1절의 "같은 날"과 맞지 않는다(9절).
- 제품 정의서 가정과 다른 점: 7절 후보 "On this day"는 1순위가 될 수 없다. 5절 4번 "정확히 같은 날짜의 국내 사건"은 날짜에 따라 비어 있을 수 있다(1995-03-15). 6.3절 `tone` 은 구조화 데이터만으로 판정할 수 없다(9절).

## 2. 확인할 질문과 답

질문 번호는 계획서 "T5 작업별 기준"의 번호다. 제품 정의서 7절 "M0에서 확인할 것" 4개(연·월·일 정확성, 한국어 데이터 양, 이미지 라이선스 메타데이터, 국내 사건 날짜별 조회 가능 여부)는 질문 열에 `(7절)` 로 표시했다. 출처 약칭은 다음과 같다.

- **OTD**: Wikimedia "On this day" 피드(Wikifeeds API). `{lang}.wikipedia.org/api/rest_v1/feed/onthisday/...` 와 `api.wikimedia.org/feed/v1/wikipedia/{lang}/onthisday/...` 두 경로
- **Wikidata**: Wikidata Query Service(SPARQL)와 Wikibase Action API
- **위키백과 날짜 문서**: 한국어 위키백과의 날짜 문서("9월 17일")와 연도 문서("1988년"). MediaWiki Action API `action=parse` 로 읽는다. 비교용으로 영어 날짜 문서도 열었다
- **Commons**: Wikimedia Commons의 사건 대표 이미지 경로(날짜 범주, 사건 범주, 위키백과 문서 대표 이미지)
- **국가기록원**: 국가기록원 기록물(나라기록물 검색 OpenAPI, 주제 콘텐츠 연표)
- **대한뉴스**: 대한뉴스 회차 목록(e영상역사관 대한뉴스관, 공공데이터포털 대한뉴스관 파일)

## 3. 출처 카드

검토했지만 카드로 쓰지 않은 것: 영어 위키백과 `Portal:Current events/<날짜>` 는 1988-09-17·1995-03-15 문서가 없고 2002-06-22 문서는 490바이트뿐이다 [44]. 영어 "1995 in South Korea" 같은 연도별 국가 문서에도 1995-03-15 항목이 없다 [45]. 둘 다 한국어 날짜·연도 문서보다 나을 것이 없어 추가 후보로 올리지 않았다.

## 4. 미디어 레코드 필드 매핑

사건 미디어만 다룬다. 사건 텍스트 필드는 아래 "사건 레코드 필드 제안"에 있다. OTD 썸네일과 Wikidata P18은 결국 Commons(또는 로컬 위키) 파일이라 라이선스는 Commons 열의 방법으로 다시 조회한다. 위키백과 날짜 문서는 이미지를 주지 않는다. `link_only` 레코드에서 `url`·`thumbnail_url` 을 비우는 문제는 T4 9절·T3 D3과 같다.

결론:
- **Commons**: 비상업·상업 모두, 파일이 Commons 저장소에 있고 `NonFree` 가 없고 라이선스가 허용 목록이면 `embed` 한다. 작가·라이선스·라이선스 링크·원문 페이지를 함께 보여 준다 [22][46][47]. 상업이면 알아볼 수 있는 인물 사진은 `link_only` 로 내리는 편이 안전하다(T4 [77]). 핫링크를 권장하지 않으므로 사본을 둘지는 T4 D6과 함께 정한다.
- **OTD 썸네일**: 그대로는 비상업·상업 모두 `link_only`. 파일 이름으로 라이선스를 조회해 Commons 열 규칙을 통과할 때만 `embed` 한다. 비자유 로컬 파일(로고 등)과 사건과 무관한 문서 이미지(국가 문서 등)가 섞이므로 [8][63], 사건 문서 자체(날짜가 맞는 QID)의 이미지만 고른다.
- **Wikidata P18**: Commons 파일 이름이라 Commons 열과 같다. 사건 날짜를 촬영일로 옮기지 않는다.
- **위키백과 날짜 문서**: 텍스트 출처라 미디어 레코드를 만들지 않는다. 이미지는 링크된 문서의 PageImages(`pilicense=free`) → Commons 열 [48][65].
- **국가기록원·대한뉴스**: 비상업·상업 모두 `link_only` (T4 4절 결론과 같음).
- **e영상역사관 국가기록사진**(국내 사건의 같은 날 사진, 1988-09-17·2002-06-22): T4 결론대로 비상업 + T4 D2·D3 허용일 때만 `embed`, 그 외 `link_only`.

### 사건 레코드 필드 제안

M3a 계획서의 입력이다. 확정이 아니다. 미디어는 6.2절 미디어 레코드를 `media[]` 로 참조한다.

| 필드 | 설명 | 채우는 곳 (예) |
|---|---|---|
| `id` | 고유 ID | 계산: Wikidata QID가 있으면 `wd-Q60787007`, 없으면 `kowiki-<날짜 문서>-<줄 해시>` |
| `date` | 사건 날짜 `YYYY-MM-DD` (입력 생년월일과 같아야만 노출) | 날짜 문서의 월·일 + 줄의 연도 [33], Wikidata P585·P580 [25] |
| `date_source_precision` | 원천 날짜의 정밀도. `day` 가 아니면 "그날의 사건"에 넣지 않는다 | Wikidata `precision` 11 [28], 날짜 문서는 `day` |

## 6. PM이 실행할 확인 명령

Wikimedia 계열(OTD, Wikidata, 위키백과, Commons)은 키가 필요 없어 모든 확인을 공개 엔드포인트로 마쳤다. 국내 사건 보강 출처는 키가 필요하고, T4 6절의 명령을 그대로 쓴다. 아래에는 T5가 볼 것만 더한다. 키는 `$DATA_GO_KR_SERVICE_KEY`(공공데이터포털 서비스 키, 서버 전용, `VITE_` 없음)로만 쓴다. 응답 원문과 내려받은 파일은 저장소에 넣지 않는다.

**A1. 나라기록물 검색 OpenAPI** (T4 A1과 같은 명령, 날짜축 확인용으로 검색어만 데모 사건으로)

```bash
# 근거: https://www.archives.go.kr/next/newsearch/openAPI01.do (요청 URL 예시는 serviceKey, 요청변수 표는 key — T4 A1 참조)
curl -sS -G "https://search.archives.go.kr/openapi/search.arc" \
  --data-urlencode "serviceKey=$DATA_GO_KR_SERVICE_KEY" \
  --data-urlencode "query=서울올림픽 개막식" \
  --data-urlencode "rc_type=ritem" \
  --data-urlencode "display=10" | head -c 3000
# 응답에서 확인할 것: 각 item에 날짜 필드가 prod_year 하나뿐인지(일 단위 날짜 필드가 없는지),
#   doc_type이 C(사진)·D(동영상)인 건의 prod_year가 1988인지. 오류 1001이면 T4 A1의 key 이름으로 다시 실행.
```

**A2. 공공데이터포털 대한뉴스관 API** (T4 A2와 같은 명령)

```bash
# 근거: https://infuser.odcloud.kr/oas/docs?namespace=15050744/v1 (공공데이터포털 Swagger, serviceKey 쿼리 인증)
curl -sS -G "https://api.odcloud.kr/api/15050744/v1/uddi:f1192ad7-74f0-48f7-8104-c3ff8189ce49" \
  --data-urlencode "serviceKey=$DATA_GO_KR_SERVICE_KEY" \
  --data-urlencode "page=1" \
  --data-urlencode "perPage=5" | head -c 3000
# 응답에서 확인할 것 (T5): data[].제작일 이 YYYY-MM-DD 형식인지, data[].호수 와 함께 오는지.
```

**T4 B1 (브라우저, 키 없음)에서 T5가 볼 것**: https://www.data.go.kr/data/15050744/fileData.do 의 CSV에서 `제작일` 이 1988-09-17인 행의 `호수` 가 1715인지, 1988-09-11~1988-09-17 사이 행이 몇 개 회차인지(주간 발행 확인), 1994-12-31 이후 행이 없는지. 파일은 저장소에 넣지 않는다.

## 7. 이 영역 추천안

**그날의 사건 (M3a)**
- 1순위: **한국어 위키백과 날짜 문서 + 연도 문서** (Action API, 종합 확신도: `확인됨`). 한국어 문장, 일 단위 날짜, 데모 3개 중 2개 날짜의 국내 사건(서울 올림픽 개막, 한국-스페인 8강전)을 준다 [33][34]. CC BY-SA 4.0, 상업 이용 가능 [20].
- 함께 쓰는 것: **Wikidata 날짜 질의** (`확인됨`) — QID로 중복을 없애고, 날짜(정밀도 11)를 교차 확인하고, `tone` 의 구조화 신호(분류·사망자 수)와 세계 사건 후보를 준다 [25][28][31]. 화면 문장 원천으로는 쓰지 않는다(한국어 라벨이 드묾).
- 사건 이미지: **Wikimedia Commons** (`확인됨`) — 사건 범주·날짜 범주·PageImages(`pilicense=free`)로 찾고 `extmetadata` 로 `embed` 를 자동 판정한다 [48][51].
- 대안: **On this day 영어** (`확인됨`, 적합도 조건부) — 세계 사건을 보탤 때만. 한국어가 없고 데모 연도 항목이 거의 없으며, 2026년 7월부터 지원 중단 예정이다 [1][3]. M3a의 필수 의존으로 두지 않는다.
- 이유: 7절 후보 중 한국어와 정확한 날짜를 함께 주는 것은 한국어 위키백과뿐이다. 구조화 데이터(Wikidata)는 날짜 거르기가 정확하지만 문장이 없다. 둘을 QID로 묶으면 서로의 약점을 메운다. 날짜 문서 366개와 연도 문서는 미리 받아 캐시할 수 있어 지원 중단 위험과 속도 제한에서도 자유롭다.

**국내 사건 보강 (M3c) — MVP에 넣을 가치 판단**
- 1순위: **없음** — 자동 출처로 쓸 만한 것이 없다. 국가기록원은 날짜로 조회하는 API가 없고(연표는 웹 페이지뿐) [67][69], 대한뉴스는 1958~1994년만 있고 회차 날짜가 주간 발행일이다 [72]. 둘 다 `link_only` 다(T4).
- 대안: **대한뉴스 회차 링크 카드** (`부분 확인 (PM 호출 대기)`) — CSV `제작일` 색인으로 1958~1994년 출생자에게 "그 주의 대한뉴스" 링크를 근사 날짜 표기와 함께 보여 준다. **국가기록원 연표** (`부분 확인 (PM 호출 대기)`) — content-curator가 데모 날짜의 국내 사건을 확인하는 참고 자료로만 쓴다.
- 판단: **MVP(M3c)에는 넣지 않는 것을 추천한다.** 데모 3개 날짜에서 국내 보강 출처가 위키백과보다 더 준 사건이 없다(1988-09-17은 이미 위키백과·Wikidata에 있고, 1995-03-15·2002-06-22는 연표에도 없음) [33][69]~[71]. 대한뉴스 카드는 1995·2002 데모에 해당이 없어 MVP 완료 조건(데모 3개)에 기여하지 않는다. MVP 뒤에 넣는다면 대한뉴스 링크 카드가 비용 대비 가장 낫다(CSV 한 번 색인, 키 불필요). 결정은 10절 D5.

## 8. 위험

1. **On this day 지원 중단.** Wikifeeds API는 2026년 7월부터 점진적 지원 중단 예정이고 대체 경로가 정해지지 않았다 [1]. RESTBase(`/api/rest_v1/`)도 지원 중단 대상이고 [17][18], API Portal은 2026년 6월에 닫혔다 [16]. 지금은 두 경로 모두 응답하지만 [6][12] 언제 끊길지 모른다.
2. **Wikidata Query Service 백엔드 이전.** 2026~2027년에 새 백엔드로 옮기며 v2 엔드포인트가 생기고 질의를 고쳐야 할 수 있다 [24]. 같은 질의도 패턴에 따라 0행이 나왔다(3절 Wikidata 카드 주의). 어댑터 테스트를 녹화 fixture로 두고 주소를 설정값으로 뺀다.
3. **날짜가 비는 날이 있다.** 1995-03-15는 한국어 위키백과·국가기록원·Commons 모두 국내 항목이 없다 [35][38][61][70]. 생년월일에 따라 "그날의 세계" 섹션이 비거나 잡음 섞인 Wikidata 항목만 남는다(D2).
4. **비자유 이미지 혼입.** REST 요약·OTD의 `thumbnail` 은 영어 위키백과 로컬의 공정 이용 로고를 그대로 준다 [62][63]. 이 필드를 그대로 쓰면 6.2절을 어긴다. PageImages `pilicense=free` 나 `NonFree`·`imagerepository` 검사가 필수다.
5. **사건과 무관한 이미지.** OTD `pages[]` 에는 "Iran" 같은 일반 문서가 섞여 그 이미지가 사건 이미지처럼 보일 수 있다 [8]. 날짜가 맞는 사건 QID의 문서 이미지만 쓴다.
6. **같은 사건의 수치가 출처마다 다르다.** 2002년 이란 지진 사망자를 OTD `events` 는 "at least 261", `selected` 는 "at least 230"으로 적는다 [8][9]. 수치를 고쳐 쓰지 말고 원문 그대로 인용하고 출처 링크를 단다.
7. **`tone` 오판.** 구조화 규칙은 2016년 뉴욕·뉴저지 폭탄 사건을 놓쳤다 [32]. 키워드 규칙은 오탐이 있다. 판정이 불확실하면 `tragic` 으로 두고(로드맵), 데모 날짜는 사람이 확인한다.
8. **User-Agent를 안 보내면 분당 10회.** 연락처가 든 User-Agent가 없으면 분당 10회로 제한되고 차단될 수 있다 [13][21]. 환경변수 `WIKIMEDIA_USER_AGENT`(서버 전용, `VITE_` 없음)를 제안한다. 값 형식은 `TheWorldThatDay/<버전> (<연락처 URL 또는 이메일>)` [21]. 연락처 값은 PM이 정한다(D7).
9. **위키텍스트 파싱이 깨지기 쉽다.** 날짜 문서는 사람이 편집하는 자유 형식이다. 한 연도에 여러 사건을 하위 줄로 나누거나, 같은 사건을 "사건"과 "문화"에 나눠 적는다 [33][34]. 판 번호(`revid`)를 저장해 어느 판을 읽었는지 남긴다 [39].
10. **인물 사진.** 1988 개막식 성화 점화 사진에는 이름이 알려진 인물이 나온다 [51]. 상업이면 동의 문제가 남는다(T4 [77]).
11. **응답 크기.** OTD 응답 하나가 250~490KB다 [6][8]. 요청마다 부르면 10초 목표(8절)를 위협하고 속도 제한에 걸린다. 월·일 단위로 캐시한다.

## 10. PM 결정 필요

아래 결정은 다음 M0 작업(T6)을 막지 않는다. T6 `summary.md` 6절에 모아 한 번에 결정한다. 이 판단들은 법률 자문이 아니다.

**D1. 그날의 사건 1순위 조합** (관련: 로드맵 "M0 이후 확정: 사건 출처 1순위", M3a)
- 선택지:
  - (a) 한국어 위키백과 날짜·연도 문서(문장) + Wikidata(QID·교차 확인·`tone` 신호) + Commons(이미지). OTD 없음.
  - (b) (a)에 OTD 영어를 선택 어댑터로 더한다(실패·중단 시 그 부분만 비움).
  - (c) Wikidata만(문장은 라벨로).
- 추천안: (a). 세계 사건이 너무 적으면 M3a 계획 때 (b)를 다시 본다.

**D2. 그날 기록된 사건이 없을 때** (관련: 5절 4번, 6.1절, M3a·M3b)
- 근거: 1995-03-15 결과(5절).
- 선택지:
  - (a) "이 날짜에 기록된 큰 사건을 찾지 못했다"고 정직하게 안내하고, 섹션에는 같은 날 사진(있으면)만 둔다.
  - (b) 같은 달의 사건으로 넓히되 "같은 달" 표기를 붙인다(6.1절 표기 재사용).
  - (c) 섹션을 숨긴다.
- 추천안: (a). (b)는 5절 4번 "정확히 같은 날짜"를 바꾸는 일이라 PM이 정한다.

**D3. `tone` 판정 방식** (관련: 6.3절, 로드맵 "`tone` 판정 방식", M3a)
- 선택지: (a) 구조화 규칙만, (b) 큐레이션 목록만, (c) 구조화 + 키워드 규칙에 큐레이션 덮어쓰기, 불확실하면 `tragic`.
- 추천안: (c). 근거는 4절 아래 비교표.

**D4. 위키백과 문장을 고쳐 쓸 때의 동일조건(ShareAlike) 범위** (관련: 6.2절, M3a·M3b)
- 근거 위치: Wikimedia 이용 약관 7절 "Licensing of Content"의 수정·추가 조항과 재사용 조항 [20], 콘텐츠 재사용 안내 [22].
- 묻는 것: 위키 링크 기호만 벗기는 것이 "수정"인가, 요약·번역(영어 OTD 문장을 한국어로)한 문장을 CC BY-SA 4.0으로 내면 우리 화면의 다른 문장까지 동일조건이 미치는가.
- 선택지:
  - (a) 원문 문장을 그대로 쓰고(링크 기호 제거만), 문서 링크와 "CC BY-SA 4.0" 표기를 단다. 번역·요약하지 않는다.
  - (b) 요약·번역을 허용하고 "수정됨"과 CC BY-SA 4.0 표기를 그 문장에만 단다.
- 추천안: (a). 영어 OTD 문장은 번역하지 않으므로 D1 (a)와 맞는다.

**D5. 국내 사건 보강(M3c)을 MVP에 넣을지** (관련: 7절, 로드맵 "국내 사건 보강 포함 여부", M3c)
- 선택지:
  - (a) MVP에서 뺀다.
  - (b) 대한뉴스 회차 링크 카드만 넣는다(1958~1994년 출생, `link_only`, 근사 날짜 표기).
  - (c) 국가기록원 연표까지 큐레이션해 넣는다.
- 추천안: (a). 근거는 7절 판단.

**D6. 대한뉴스 회차 날짜 표기** (관련: 6.1절·6.2절 `date_precision`, D5가 (b)일 때만)
- 근거: 주간 발행 [72], 날짜 의미 미확인(T4 9절).
- 선택지:
  - (a) `date_precision: approx` 로 두고 캡션을 "대한뉴스 제1715호 (1988년 9월 17일 자)"처럼 회차 날짜로만 적는다.
  - (b) 6.2절에 `week` 값을 새로 넣는다(제품 정의서 수정).
  - (c) 대한뉴스를 쓰지 않는다.
- 추천안: (a).

**D7. Wikimedia User-Agent의 연락처** (관련: 8절, 환경변수, M3a)
- 근거: User-Agent 정책 [21], 속도 제한 [13].
- 선택지: (a) 저장소 URL(https://github.com/ericmschoi/The-World-That-Day)을 연락처로 쓴다, (b) PM이 정한 연락용 이메일을 `WIKIMEDIA_USER_AGENT` 에 넣는다.
- 추천안: (a). 개인 이메일을 코드나 문서에 남기지 않는다. 값은 `.env` 에 두고 키 이름만 `.env.example` 에 넣는다(M1 backend-dev).
