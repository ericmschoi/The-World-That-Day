# World section fixtures

MSW bodies for `GET /api/story/world` (plan `docs/plans/m3b2-world-events-ui.md`, "MSW fixture").
TypeScript modules, so `satisfies WorldResponse` type-checks every value, string unions included.
Tests never call the network; media files are never downloaded or copied, only their metadata.

The default handler in `../../handlers.ts` answers `1988-09-17` with `world1988WithMedia`,
`2002-06-22` with `world2002WithMedia`, `1995-03-15` with `world1995`, and every other date with a
500 without a body. Tests swap in `world1988`, `world2002` or errors with `server.use(...)`.

## Where the values come from

Events: synthetic English (plan C1 S3a, T6 (3)) in the shape of the S3a response contract in
`docs/plans/c2-english-events.md`: `summary_lang` `en`, `source_name` `English Wikipedia`,
`text_license_url` `…/by-sa/4.0/deed.en`, `source_section` `Events`, `source_url` and
`related_links[].url` on `https://en.wikipedia.org/wiki/`, `id` `enwiki-<date>-<8 hex>`, and
`date_kind` / `range_end`. The sentences were written for these fixtures; none is copied from a
Wikipedia page or a server response, and the web must not depend on them matching one. Until S3a
these were copies of the Korean server response for the same dates; the dates stay as plain demo
dates (product brief 12).

- `world1988`: event ① (1988 Summer Olympics) and event ② (`Test event B`) are `day` lines of the
  "September 17" page; event ③ (`Test event C`) is a `range_start` line of the "1988" page with
  `range_end` `1988-10-02`, so the screen shows "Started that day — ran until October 2";
- `world2002`: one `day` line of the "June 22" page (2002 FIFA World Cup);
- every demo event is `normal`, `rule:no-signal` and `world`; `source_revision` values are made up.

Media: copied value for value from `data/schema/examples/media/valid/`, with only the API-only
`date_relation` added. The two real Commons examples (original URLs, checked on 2026-10-13,
licenses) are described in `data/schema/examples/media/README.md`.
`src/world/worldFixtures.test.ts` compares every copied media value with those files.

Fixture text (plan C1 S1): plainly fake test text is English ("Test event sentence A"); values
that imitate the server's `NO_AUTHOR`/`NO_LICENSE` output follow the server's English text; values
copied from `data/` stay exactly as copied, Korean included.

The web must not depend on these matching a live server response.
